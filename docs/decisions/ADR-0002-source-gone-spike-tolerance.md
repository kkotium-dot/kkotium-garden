# ADR-0002: 공급처 단절 판정에 고립 스파이크 1회 허용 (옵션 C 채택)

> 상태: 승인 (2026-07-24)
> 결정자: 운영자 위임 → Desktop 권장안 확정
> 관련: `docs/design/SOURCE_GONE_ROBUSTNESS_TICKET_2026-07-23.md` · 원칙 #297

## 맥락

`countLeadingNegatives()`(source-gone.ts)는 최신 스냅샷부터 훑다가 **첫 양수를 만나면 즉시 중단**한다. 연속 음수 3회 이상이면 `sourceGone = true`.

문제: 공급이 실제로 끊긴 상태에서도 폴러가 **일시적으로 양수 1건을 잘못 읽으면** 카운트가 리셋되어 `sourceGone`이 **false로 고착**된다. 그러면 처분 대상이 조용히 누락된다 — 셀러는 끊긴 상품을 계속 팔리는 줄 알고 방치하게 된다.

검토한 3안:
- **A. 현행(연속 N)**: 단순하지만 노이즈 1건에 무력화됨.
- **B. 최근 M개 중 N개 음수**: 노이즈에 강하지만, **오래전 일시 품절이 계속 카운트**돼 정상 복구된 상품을 단절로 오판할 수 있다.
- **C. 연속 판정 + 고립 스파이크 1회 허용**: 음수 사이에 낀 **단발성 양수 1건은 무시**하고 연속으로 간주. 단, 양수가 **2회 연속**이면 진짜 복구로 보고 리셋.

## 결정

**우리는 옵션 C를 채택한다.**

- 판정: 최신부터 훑되, **양수가 1건만 고립되어 나타나면 건너뛰고** 연속 카운트를 이어간다.
- **양수 2건 연속** = 공급 복구로 판단, 카운트 리셋.
- 임계값 `SOURCE_GONE_MIN_CONSECUTIVE = 3`은 유지.
- 수정 지점은 **`source-gone.ts` 한 곳**(소비처 3곳이 전부 이 파일을 경유하므로 자동 전파).

**선택 근거**: 드롭십 특성상 공급 끊김은 **되돌아오지 않는 경우가 대부분**이다. 따라서 "놓치는 것"(거짓 음성)이 "성급히 단절로 보는 것"(거짓 양성)보다 **비용이 크다**. 다만 B는 과거 품절 이력까지 끌고 와 오탐이 늘므로, **노이즈 내성은 얻되 최신성은 유지하는 C**가 균형점이다.

## 결과

- **긍정**: 폴러 오독 1건으로 처분 대상이 누락되는 사고가 사라진다. 수정 범위가 파일 1개로 국소적이다. 임계값 3은 그대로라 기존 판정 결과가 급변하지 않는다.
- **부정**: 로직이 "연속"보다 미묘해져 설명이 한 줄 늘어난다. 진짜로 하루만 재입고된 상품을 단절로 볼 가능성이 아주 낮게 남는다(양수 2연속이면 해제되므로 실질 위험은 작다).
- **중립**: 테스트 6케이스 필요 — 정상연속3 / 스파이크1개낀연속 / 양수2연속리셋 / 경계(정확히3) / 스냅샷부족 / 전부양수.

## 구현 시 필수

- `source-gone.ts` 수정 후 **`scripts/smoke-disposition-channels.ts` 재실행**(#299 회귀자산).
- 판정 로직 변경이므로 **T-16·T-17**(단절 우선순위) 테스트도 함께 통과 확인.
