## 1. ★★ 트랙C-2 — 소싱 낙점 상태별 세그먼트 필터 (커밋 `e2009e6`, 로컬+DB 검증 완료)

트랙C-1로 낙점 상태(관심/소싱중/제외)를 만들었으니, C-2는 **쌓인 낙점을 상태별로 빠르게 걸러 본다**. 유료 셀러툴(셀러오션·아이템스카우트)의 소싱 관리 = 세그먼트 필터 칩 패턴.

**설계 — 요소를 늘리지 않고 기존 배지 강화(#274)**: 상단 요약 배지(⭐관심 N·🌱소싱중 M)는 표시만 했다. 여기에 **클릭=필터**를 얹어 새 UI 없이 표시+필터를 겸한다. 별도 필터 줄을 안 만들어 세로 공간을 아끼고 시선 이동 0.

**구현(SourcingRecommendWidget.tsx)**:
- `filter` state('all'|'interested'|'sourcing_started', 기본 'all').
- `displayedOpps` 파생: visibleOpps(제외 뺀 전부)에 필터 적용. 제외 접기는 이 필터와 독립(제외는 세그먼트가 아니라 숨김 축).
- 상단 요약 배지 → 세그먼트 컨트롤 승격: [전체 N][⭐관심 N][🌱소싱중 N]. 활성 칩=채워진 배경(전체 흰/관심 노랑/소싱중 초록)+shadow, 비활성=투명. 단일 선택. 카운트 0이면 해당 칩 자동 숨김.
- 필터 빈 목록 안내: 결과 0건이면 "관심/소싱 항목이 없어요" + "전체 보기"(무음 폴백 금지 #270).

**검증(로컬 브라우저 실사용 + DB 실측)**:
- 세그먼트 필터 3종: 전체 5 / 관심 2(가습기·멀티탭) / 소싱중 1(청소기) 클릭 전환 정확.
- 빈 목록 엣지: 관심 필터에서 마지막 관심 해제 → "관심 항목 없어요" 안내 + 전체 보기 버튼 + 관심 칩 자동 숨김.
- 필터-제외 독립성: 소싱중 필터 상태에서도 "제외 1건 보기" 토글 하단 유지.
- 테스트 데이터 원복: 8/6 낙점상태 NULL 복구.

## 2. ★★ GET 날짜 중복 근본수정 (route.ts, C-2 검증 중 발견 · 전 상품 공통)

**문제**: GET이 `date: { gte: todayStart }` + `take: 5`로 조회 → 날짜 경계·타임존 차이로 어제/오늘 레코드가 DB에 함께 있으면 두 날짜에서 rank=0끼리 섞여 **같은 키워드가 중복 반환**(실측: "가습기"가 8/5·8/6 두 건). 원인은 POST가 오늘 것만 deleteMany하고 과거는 안 지워 **8/3~8/6이 누적**된 것.

**수정**: "가장 최신 date 하나"만 조회(findFirst orderBy date desc → 그 date로 findMany). 소싱 스캔은 하루 1회 배치라 "최신 date=오늘 스캔"이 정확한 의미. 날짜를 조건에 안 넣어 타임존 경계 문제를 원천 차단. 검증: 중복 0, recordId 5개 정상.

**주의(UI는 원래 안전)**: 위젯은 항상 recordId로 setStatus를 호출하므로 낙점 자체는 정확했다. 문제는 GET이 같은 키워드를 2번 렌더한 것(화면 혼란).

## 3. 🌱 개선안 (다음 세션 제안) — 소싱 레코드 누적 정리

**발견**: POST가 `deleteMany({date: todayDate})`로 오늘만 지워, 과거 소싱 레코드가 무한 누적된다(8/3~8/6 실측). GET을 "최신 date만"으로 고쳐 화면은 안전하지만 DB 용량이 계속 는다.

**제안**: POST 저장 시 "N일(예: 7일) 이전 레코드 deleteMany" 추가 → 자동 정리. 또는 주간 크론에 정리 태스크. 전 상품 공통 관점의 근본책. write set: route.ts (또는 크론).
