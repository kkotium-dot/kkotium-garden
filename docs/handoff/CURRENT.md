## 3. 문서 갱신 시스템 신설 (오늘 확정)

**배경**: 대표님 요청 — "매일 프로젝트 마무리가 되면 문서 갱신하는 시스템", "스킬/에이전트 도입 시 함께 재점검".

**결정**: hooks(자동 셸 실행) 도입은 하지 않음 — 이 프로젝트가 이미 명시적으로 거부한 이유(네이버 PUT·디스코드 실발송 같은 비가역 액션이 자동 트리거될 위험)가 여전히 유효. 업계 조사 결과도 "auto memory/hooks가 캡처한 게 실제 팀 결정이면 반드시 버전관리 파일로 옮겨야 한다"는 원칙이 공통적이었음 — 이미 이 프로젝트의 다중 문서 체계(CURRENT.md/TRACKER/PRINCIPLES_LEARNED)가 그 방식.

**구현**: CLAUDE.md "HOW — 작업 흐름 규칙"에 **#319 세션 종료 시 문서 3종 점검**을 상시 규칙으로 추가(작업 완료의 정의에 포함, 스킵 시 "완료" 보고 금지). "절대 금지·원칙 인덱스" 섹션의 "AI 인프라 변경 시" 문구에 **스킬·서브에이전트·hooks·MCP 서버 도입도 포함**됨을 명시하고, 도입 시 이 문서 갱신 규율과의 충돌 여부를 재검토하도록 트리거를 심어둠.
