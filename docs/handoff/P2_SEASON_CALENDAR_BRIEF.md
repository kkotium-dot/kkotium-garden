## 1. 왜 이 작업이 필요한가

운영자 요구: *"시즌별 전략상품·니치 상품을 제안하는 시스템"*.
그런데 현행 시즌 판정 로직이 너무 빈약해서 **시즌 추천이 사실상 작동하지 않는다.**

### 현행 구현 실측 (`src/lib/discord.ts:33~50`)

```ts
export function getSeasonContext(): { label: string; daysLeft: number; words: string[] } | null {
  const EVENTS = [
    { month: 2,  day: 14, label: '발렌타인데이', words: ['초콜릿','발렌타인','선물','포장'] },
    { month: 3,  day: 14, label: '화이트데이',   words: ['사탕','화이트','선물','포장'] },
    { month: 5,  day: 5,  label: '어린이날',     words: ['장난감','어린이','선물','놀이'] },
    { month: 5,  day: 8,  label: '어버이날',     words: ['카네이션','선물','부모님'] },
    { month: 11, day: 11, label: '빼빼로데이',   words: ['빼빼로','과자','선물','포장'] },
    { month: 12, day: 25, label: '크리스마스',   words: ['크리스마스','산타','선물','트리'] },
  ];
  // diff >= 0 && diff <= 30 이면 반환, 아니면 null
}
```

### 확인된 구조적 결함 5가지

| # | 결함 | 왜 문제인가 |
|---|---|---|
| 1 | **이벤트 6개뿐** | 설·추석·신학기·장마·김장·블프·이사철·여름가전·겨울가전 등 **전부 누락** |
| 2 | **리드타임 전 이벤트 30일 고정** | 크리스마스 소싱은 D-45~60에 시작해야 하는데 D-30에 알려주면 이미 늦다. 이벤트마다 필요한 준비 기간이 다르다 |
| 3 | **음력 표현 불가** | `{month, day}` 구조라 **설날·추석을 아예 넣을 수 없다**(음력이라 매년 양력 날짜가 바뀜). 한국 커머스 최대 성수기 2개가 구조적으로 배제된 상태 |
| 4 | **첫 매치 하나만 반환** | 시즌이 겹칠 때(예: 5월 어린이날+어버이날) 하나만 잡힘 |
| 5 | **키워드 4개뿐, 카테고리 매핑 없음** | 소싱 엔진이 "어떤 카테고리를 뒤져야 하는지" 알 수 없다 |

**여기서 3번이 가장 치명적이다.** 식품·화장품·브랜드를 제외한 우리 취급 범위(생활/주방/인테리어/디지털 등)에서 설·추석은 **선물세트·제수용품·주방용품·이사/집들이** 수요가 폭증하는 시기인데 시스템이 이걸 전혀 모른다.

## 2. 산출물 (Deliverable)

### 2-1. 데이터 파일 (주 산출물)

`docs/design/SEASON_CALENDAR_DATA_2026.md` — Code가 TypeScript로 옮길 수 있는 **구조화된 표**.

각 이벤트마다 다음을 채운다:

| 필드 | 설명 | 예시 |
|---|---|---|
| `id` | 영문 슬러그 | `chuseok` |
| `label` | 한글 표기(화면 노출용) | `추석` |
| `type` | `solar`(양력 고정) / `lunar`(음력) / `range`(기간형) | `lunar` |
| `date` | 양력이면 `{month, day}`, 음력이면 **2026~2028 양력 환산일 명시** | 2026-09-25 / 2027-09-15 … |
| `leadTimeDays` | **소싱을 시작해야 하는 D-일수** | 45 |
| `peakWindowDays` | 판매 피크 구간(D-N ~ D-day) | 14 |
| `keywords` | 검색 키워드(소싱 엔진이 DataLab에 던질 시드) | 선물세트, 명절선물, 제수용품… |
| `categoryHints` | 네이버 d1/d2 힌트(취급 제외 카테고리는 넣지 말 것) | 생활/건강 > 주방용품 |
| `note` | 셀러 실무 관점 메모 | 배송 마감·택배 물량 폭주 주의 |
| `confidence` | `high`/`medium` — 근거 강도 | high |

### 2-2. 설계 메모

`docs/design/SEASON_CALENDAR_DESIGN.md` — 음력 처리 방식, 겹침 처리 방식, 리드타임 계산식 제안.

## 3. 리서치 범위 (최소 20개 이벤트 목표)

**반드시 포함**(현재 전부 누락):
- **명절(음력)**: 설날, 추석 — 2026·2027·2028 양력 환산 필수
- **기념일**: 발렌타인, 화이트데이, 어린이날, 어버이날, 스승의날, 빼빼로데이, 크리스마스 (기존 6개 유지·보강)
- **생활 주기**: 신학기(3월·9월), 이사철(봄·가을), 김장철(11월), 장마(6~7월), 혹서기(7~8월), 혹한기(12~1월)
- **쇼핑 이벤트**: 블랙프라이데이, 코리아세일페스타, 광군제(11.11)
- **계절 전환**: 봄맞이 대청소, 여름가전(선풍기·서큘레이터), 겨울가전(난방·가습기), 캠핑 시즌

**제외**(운영자 확정 취급 제외 정책, PRD §5-2): 식품·화장품·브랜드 상품 관련 키워드는 넣지 말 것. 예를 들어 설 선물세트를 다룰 때 **식품 세트가 아니라 생활용품·주방용품·인테리어 선물** 방향으로 키워드를 잡는다.

- ❌ **코드 파일 수정 금지**. 이 작업의 산출물은 **문서 2건뿐**이다. TypeScript 구현은 Code 레인이 나중에 담당한다.
