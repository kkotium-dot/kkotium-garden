## ★★★ #1 — 씨앗심기 카테고리 추천이 "가구/인테리어"로 대량 오분류 (최우선, 확정 원인)

### 증상
운영자 발견: 거의 모든 상품이 "가구고리"류 카테고리로 추천됨.

### ★ Desktop 실측으로 근본 원인 확정
`/api/category/suggest` (`src/app/api/category/suggest/route.ts`)를 실제 호출해 재현 성공:
```
"반려동물 장난감 세트" → 가구/인테리어>DIY자재/용품>가구부속품  (완전히 무관!)
"스마트폰 거치대"      → 가구/인테리어>DIY자재/용품>가구부속품  (완전히 무관!)
"미니 선물세트"        → 가구/인테리어>인테리어소품>기타장식용품
"휴대용 정리함"        → 가구/인테리어>인테리어소품>기타장식용품
```
전부 `usedAI: true`(AI가 답했는데도 오분류).

**확정 원인 — `suggestWithGroq()`의 AI 프롬프트 안에 있는 이 한 줄**:
```
- For unknown items: use 가구/인테리어 > DIY자재/용품 > 기타DIY자재/용품
```
AI(Groq)가 상품명을 정확히 분류 못 할 때마다 이 지시를 그대로 따라 "가구/인테리어"로 도피. `validateSuggestion()`이 DB 검증을 거치며 실제로 가장 가까운 항목(`가구부속품`, `기타장식용품` 등)에 fuzzy 매칭되어 결과에 노출됨.

**★ 2차 확인 — 시스템 기본값 코드 자체가 이 카테고리를 가리킴**:
`naver-categories-full.ts` 17행: `['50003307','가구/인테리어','DIY자재/용품','가구부속품','가구다리']`
그런데 `50003307`은 다른 코드(`upload-readiness/auto-fill/route.ts` PATCH)에서 **"empty or default category"(미분류 기본값)로 명시적으로 취급**되는 코드다. 즉 "미분류 기본값"이 우연히도 "가구부속품 > 가구다리"라는 실제 카테고리와 겹쳐 있어 이중으로 혼란을 유발.

### 근본 수정 방향 (전 상품 공통, 단건 아님)
1. **AI 프롬프트에서 "For unknown items: use 가구/인테리어..." 지시 완전 삭제.** 모르면 폴백 카테고리를 강제하지 말고, AI가 신뢰도 낮은 답이라도 실제 상품 특성에 맞게 추론하도록 유도하거나, 차라리 **빈 배열을 반환**하게 해 `suggestFallback()`(키워드 규칙)으로 자연스럽게 넘어가게 한다.
2. `suggestFallback()`도 매칭 없으면 빈 배열 반환 — 이 경로도 확인해 "강제 기본 카테고리"로 채우는 곳이 없는지 전수 점검(`FALLBACK_RULES` 끝에 와일드카드 규칙 없는지 재확인, 있다면 제거).
3. **결과가 비었을 때 UI가 어떻게 되는지도 확인**: "카테고리를 못 찾았습니다 — 직접 선택해주세요" 같은 정직한 빈 상태가 나와야지, 억지로 아무 카테고리나 채우면 안 됨(#310 정신 — 미확실할 때 지어내지 않기, #325 정직한 미달성 표시).
4. `50003307`이 "기본값 코드"로 하드코딩된 다른 위치도 전수 검색(`grep -rn "50003307"`)해서, 실제 유효 카테고리(가구다리)와 "미분류 센티널"이 충돌하지 않게 — **센티널은 존재하지 않는 코드(예: 빈 문자열 `''`)로 바꾸는 게 근본적**일 수 있음. 영향 범위 파악 후 신중히 결정.
5. `validateSuggestion()`의 fuzzy 매칭(d1+d2 매칭만으로 아무 d3나 골라주는 `d1d2[0]` 폴백, 3번 케이스 char-overlap 50%)도 오분류를 도울 수 있음 — 기준 재검토.

### write set
`src/app/api/category/suggest/route.ts` (프롬프트 수정 핵심) + `src/lib/naver/naver-categories-full.ts`(50003307 센티널 재검토 시) — 신중히, 다른 곳에서 이 상수를 참조하는 전 지점 확인 후.

### 검증 방법
1. 코드 수정 후 위 5개 테스트 케이스(반려동물 장난감·스마트폰 거치대·미니 선물세트·휴대용 정리함·캠핑용 접이식 테이블)를 다시 호출해 "가구/인테리어" 쏠림이 해소됐는지 확인.
2. 실제 DB의 여러 미분류 상품(`naverCategoryCode='50003307'`)으로 재실행해 다양한 카테고리가 나오는지(전부 가구/인테리어가 아닌지) 확인.
3. 정상 매칭 케이스(가습기→계절가전, 잠옷→여성언더웨어/잠옷 등)는 회귀 없는지 확인.

2. 네이버 상품 API 응답에서 "할인 적용가"에 해당하는 필드가 정확히 무엇인지(예: `discountedSalePrice`, `salePrice` - 즉시할인 등) 확인 후, 가져오기 로직이 그 필드를 올바르게 채우고 있는지 점검.
3. 근본 수정: 마진 계산의 기준가를 실제 판매(할인 적용 후) 금액으로 통일 — 전 상품 공통(#55).

## #5 — 씨앗심기로 옮길 때 기존 가져온 상품 정보가 전부 리셋됨

### 증상
네이버에서 가져온 상품 정보(이미 채워진 필드들)가 씨앗심기로 넘어가면서 전부 사라져, 운영자가 모든 정보를 처음부터 재입력해야 함. 특히 "정보를 수정·업데이트해서 다시 네이버에 재연동"하려는 워크플로우(기존 상품 개선)에서 매우 불편.

### 요청 사항 (자동화 개선, 전 상품 공통)
- 기존 정보(이름·설명·이미지·카테고리·가격 등)를 **최대한 유지한 채로** 씨앗심기 화면에 프리필(pre-fill).
- 셀러는 "바뀐 부분만" 수정하면 되도록 — 처음부터 재입력하는 수고 제거.
- **이미지도 별도로 손 안 댄 것은 기존 그대로 유지**되어야 함(#6과 연결).

### 조사 방법
1. "가져오기 → 씨앗심기 이동" 경로에서 상태(state)가 어디서 초기화되는지 추적(`src/app/products/new/page.tsx` 진입 시 props/query/state 전달 경로 확인).
2. 네이버에서 가져온 원본 데이터가 어디(DB든 임시 상태든)에 남아있는지 확인 후, 씨앗심기 폼 초기값으로 그 데이터를 정확히 매핑.

### write set
