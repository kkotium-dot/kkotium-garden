### ★ #315 판정 — "PRD 없으면 어떤 반복 문제가 생기는가?"

**답할 수 있는 반복 문제 2건 (실제 이번 사이클에서 발생)**:
1. **범위 확대(scope creep)**: PUBLISH_REVIEW_GATE v1이 "화면 연결"로 좁게 잡혔다가 v2에서 "4경로 게이트"로 커짐. **비목표·영향범위를 착수 전 고정했으면** v1 폐기 재작성을 줄였을 수 있다.
2. **수용 기준 부재로 "완료" 판정 흔들림**: "게이트 완료 = 우회 0건"이라는 수용 기준이 #311로 사후 정립됨. 착수 전 Given/When/Then이 있었으면 P0 누락을 조기 발견.

**그러나 전면 PRD 도입은 미채택. 대신 경량 채택**:
| 결정 | 사유 |
|---|---|
| ❌ 별도 `PRD.md` 폴더/파일군 신설 | 1인 운영. design/ 시점문서가 이미 요구사항·설계를 담음. PRD 파일을 또 만들면 **이중 관리**(#313 문서는 비용) |
| ✅ **design 시점문서에 PRD 3요소 헤더 채택** | "비목표 · 수용기준(G/W/T) · 영향범위(UI/API/DB/테스트/문서)" 3블록을 **설계문서 상단 표준 섹션**으로. 신설 파일 0, 기존 문서 보강 |

→ #315 충족: PRD의 **고유 가치(비목표·수용기준)**는 실제 반복 문제(scope creep·완료 흔들림)에 답하나, **전용 파일**은 반복 문제에 답 못 함(design/이 대체). 그래서 "파일 신설 ✗ / 3요소를 기존 설계문서에 ○".
