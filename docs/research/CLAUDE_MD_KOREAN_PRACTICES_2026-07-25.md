## 2. ★ 가장 중요한 발견 — 좋은 규칙 vs 나쁜 규칙

**나쁜 규칙** (행동 기준 없음 → Claude가 실행 불가)
```
- 코드를 예쁘게 작성한다.
- 테스트를 잘 한다.
- 보안을 조심한다.
```

**좋은 규칙** (구체적 파일·명령·조건)
```
- React 컴포넌트는 src/components 아래, 페이지 전용은 src/pages/*/_components
- API 변경 후에는 npm run test:api 실행
- .env, .env.*, secrets/ 아래 파일은 읽거나 출력하지 않는다
```

> **판별 기준**: Claude가 **행동으로 옮길 수 있는가**. 추상적 표현은 컨텍스트만 먹고 아무것도 바꾸지 않는다.

## 3. ★ Karpathy 행동 가이드라인 — 운영자 상시 요구와 일치

첨부 자료(퀵레퍼런스 §B)에 실린 Andrej Karpathy(전 OpenAI/Tesla AI 디렉터)의 LLM 행동 교정 템플릿이, **운영자가 매 세션 반복해 요구해온 내용과 거의 그대로 일치**한다. 매번 프롬프트에 붙이는 대신 CLAUDE.md에 넣으면 반복 비용이 사라진다.

| Karpathy 원문 | 운영자 상시 요구 |
|---|---|
| 가정을 명시하라. 불확실하면 물어봐라. 해석이 여러 개면 전부 제시하고 혼자 골라 진행하지 마라 | "거짓말이나 임의의 결과를 꾸며내지 말고 즉각 사실대로 보고" |
| 요청하지 않은 기능·추상화 추가 금지. 200줄을 50줄로 쓸 수 있으면 다시 써라 | "요청한 부분만" |
| 인접 코드를 '개선'하지 마라. 깨지지 않은 것을 리팩토링하지 마라. **모든 변경된 줄은 사용자 요청으로 추적 가능해야 한다** | "단건 수습 금지"의 반대편 안전장치 |
| "버그 수정" → "재현 테스트 작성 후 통과시키기". 다단계 작업은 계획 먼저 + 각 단계마다 검증 방법 명시 | "근본 원인 해결" · "검증 절차 필수" |

→ **CLAUDE.md에 압축 블록으로 삽입 권장**(약 12줄). 전 레인 공통 적용.
