# 도매매칭 avgPrice 역산 로직 — 음수 마진 근본원인 & 수정안

> 작성일: 2026-08-04 | 작성 컨텍스트: Desktop 세션(rev97 후속)
> 대상: `src/lib/sourcing-recommender.ts` Step 6 (avgPrice 추정 블록)
> 발견 경위: 도매꾹 API 404 수정 후 dry-run 재검증 중 텐트(-367%)·아이스박스(-61%) 등 음수 마진 노출 확인

## 1. 근본 원인

```ts
// 현재 코드 (sourcing-recommender.ts Step 6)
const cheapest = cleanMatches.reduce((a, b) => (a.supplyPrice < b.supplyPrice ? a : b));
const estimatedAvgPrice = Math.round(cheapest.supplyPrice / 0.35);
opp.avgPrice = estimatedAvgPrice;
// ... 이후 wholesaleMatches 전체(cheapest 포함, 비-cheapest도 포함)의
//     estimatedMargin을 이 하나의 estimatedAvgPrice로 재계산
```

**결함**: 도매매칭 API(`market=dome|supply`, `kw=` 검색)는 **키워드 매칭**이지 **동일 상품 매칭**이 아니다. 예를 들어 키워드 "텐트"의 매칭 결과는:
- 샌드팩(모래주머니, 캠핑 소품) 1,100원
- 샤워텐트(실제 텐트류) 14,500원
- 모기장(캠핑 소품) 6,500원

이 3개는 **서로 다른 상품 카테고리**다. `cheapest`(샌드팩 1,100원)를 "텐트의 대표 공급가"로 오인해 `avgPrice = 1,100/0.35 ≈ 3,143원`을 역산하면, 실제 텐트 상품(14,500원)의 마진이 `(3,143-14,500)/3,143 ≈ -367%`로 폭발한다.

**근본 원인 요약**: "검색어로 찾은 도매 상품 목록의 최저가"를 "그 키워드 카테고리의 대표 판매가"로 치환하는 가정이 틀렸다. 도매매칭 API가 키워드 전문검색이라 이종 상품이 섞이는 게 정상이므로, 이 가정은 구조적으로 깨진다.

## 2. 왜 지금까지 안 보였나

이전 세션(rev96)까지는 도매매칭이 전량 0건이라 이 avgPrice 역산 블록 자체가 실행되지 않았다(`cleanMatches.length > 0` 분기 진입 불가). 이번 세션 도매꾹 API 수정으로 매칭이 살아나면서 처음으로 이 로직이 실행됐고, 잠복해 있던 결함이 드러났다.

## 3. 수정 방향 (제안, 미구현 — 운영자 확인 후 착수)

### 방향 A — 상품별 개별 마진 표시로 전환 (권장)
- "키워드 대표가격(avgPrice)"이라는 개념 자체를 버린다. `opp.avgPrice`는 계속 0(미확인)으로 두고, **각 도매매칭 상품(`wholesaleMatches[]`)의 마진을 개별 계산하지 않는다** — SE05로 실제 판매가를 모르는 이상 상품 단위 마진도 지어낼 수 없다.
- 대신 `estimatedMargin`을 `-1`(미확인) 그대로 유지 → 디스코드 표시에서 "마진 미확인 — 도매가만 참고"로 표기.
- 장점: 가짜 신호 완전 제거, SE05 원칙(§NAVER_SHOPPING_API_SUNSET_RESPONSE.md "가짜값 채우기 금지")과 완전 정합.
- 단점: 마진 정보가 아예 안 보임 → 대표님이 판단할 정보가 줄어듦.

### 방향 B — 상품명 유사도로 이종상품 배제 후 역산 (더 정교하나 복잡)
- `cheapest` 선정 전에 도매매칭 상품명이 검색 키워드를 포함하는지(또는 유사도 임계값) 체크 → 이종상품(샌드팩 등) 제외 후 남은 것 중 최저가로 역산.
- 리스크: 상품명 매칭 휴리스틱 자체가 또 다른 오탐 소스가 될 수 있음(#324 정신 위배 소지).

### 방향 C — avgPrice 대신 "공급가 범위"만 표시 (중간 절충, 이번 제안 1순위)
- 마진 계산(퍼센트)을 아예 포기하고, `wholesaleMatches`의 공급가 **범위**(최저~최고)만 사실 그대로 노출.
- 디스코드 문구를 "예상 순마진 X%" → "도매 공급가 1,100원~14,500원 확인됨 — 판매가는 직접 책정해주세요"로 변경.
- 장점: 방향A보다 정보량이 많으면서도 지어낸 숫자가 0.

## 4. 시스템 레벨 확장 범위 (단건 수습 금지 원칙 적용)

이 avgPrice 역산 블록은 `sourcing-recommender.ts` 1곳에만 있지만, **동일한 "키워드=상품" 오류 패턴**이 다른 곳에도 있는지 확인 필요:
- `wholesale-matcher.ts`의 `buildWholesaleMatchField`(Discord embed helper) — 여기도 마진 아이콘(`:green_heart:` 등)을 개별 상품 `estimatedMargin`으로 표시하므로, avgPrice가 상위에서 오염되면 여기도 오염된 값을 그대로 노출한다. 방향 A/C 적용 시 이 헬퍼도 함께 수정 필요.
