## 1. 대표님이 정확히 원하시는 최종 그림 (2026-09-23 확정)

1. 꽃단장 작업실 안에 **Gemini 채팅**이 연결돼, 그 안에서 대화로
   Gemini의 이미지 생성(create)을 반복 호출해 썸네일을 만든다.
2. 만들어진 썸네일들을 재료로 **네이버 스토어용 상세페이지 HTML**을
   만든다 — 경우에 따라 Gemini의 @Canva 기능도 상황에 맞게 활용
   (단, @Canva 자체 자동화는 API로 불가능함이 확정됐으므로, 실제로는
   "Canva에서 열어 편집" 핸드오프로 구현).
3. Gemini 이미지 생성이 막히면(quota 등) **Adobe Firefly로 자동
   전환**해 계속 작업 가능하게 한다.
4. 좋은 결과(프롬프트, 카피셋)는 **팔레트로 저장**해 다른 상품
   작업 시 재사용한다(선택 시 Context Caching으로 톤앤매너 일관성
   +비용 절감).

## 2. 최종 확정 설계 — 정확히 무엇을 만드는가

### 2-A. 인앱 채팅 UI — 정정(2026-09-23 재조사): 완전 신규가 아니라 기존 HITL 흐름 업그레이드
**결정적 발견(IDIOM-9 재확인 절차 적용)**: `ThumbnailCard.tsx`에
이미 "HITL(Human-in-the-loop) Firefly 워크플로우"가 4단계로 완성돼
있었음 — `AiQueueStepper`(4단계 진행표시) + `FireflyPromptBuilder`
(6요소 프롬프트 자동합성 → 클립보드복사 → `firefly.adobe.com` 새 탭
열기, 코드주석에 "Runtime external image generation = 0 (#38)" 명시)
+ `AssetDropZone`(Firefly에서 만든 결과물을 다시 업로드). 즉 대표님이
원하신 "Firefly로 넘겨서 자연스럽게 만들기"는 **이미 완성돼 있었고**,
새로 만들 필요가 없음 — 착수 전 `grep FireflyPromptBuilder`로 재확인,
원칙#388/IDIOM-9(브릿지 전 소비처 확인)를 정확히 적용한 사례.

**정확한 진짜 갭**: 기존 흐름의 1단계("프롬프트 준비")가 정적인
"6요소 자동 합성"뿐이라, 대표님이 "안 예쁘게 나왔다"고 느끼면 조정할
방법이 없었음(프롬프트 요소를 텍스트로만 오버라이드 가능, 대화형
아님). **채팅 UI는 이 1단계를 "Gemini와 대화하며 프롬프트를 다듬고,
image-engine.ts(rev213)의 무료 엔진으로 미리보기까지 즉시 확인한
뒤, 확정되면 기존 FireflyPromptBuilder로 넘기거나 그대로 무료
엔진 결과를 채택"하는 형태로 확장하는 것 — 완전 신규 컴포넌트가
아니라 ThumbnailCard의 기존 HITL 섹션 안에 "대화형 프리뷰" 단계를
추가하는 근본수정.**

- 중앙 컴포넌트: 기존 `AiQueueStepper`+`FireflyPromptBuilder` 흐름
  앞에 채팅 메시지 리스트+입력창+미리보기 그리드를 얹는 신규
  독립 컴포넌트(원칙#391 CDD — SRP를 지켜 별도 파일로 분리, 기존
  `ThumbnailCard.tsx`는 최소한만 수정).
- 백엔드: `/api/ai/generate-image`(rev213, image-engine.ts 어댑터)를
  그대로 재사용 — 별도 채팅 API 불필요, 프론트가 대화 히스토리를
  들고 있다가 매 턴마다 이 API를 호출하는 구조로 충분(멀티턴 이미지
  편집은 `referenceImages`로 이전 결과를 다음 요청에 포함).
- 우측 "관제탑"(25%, 이미 존재)은 그대로 유지, 네이버 SEO 신호등
  변경 없음.
- **결과물 선택**: 대화로 완성된 결과를 셀러가 (a) HTML 상세페이지
  (기존 8단계 파이프라인, #47) 또는 (b) 아래 2-B'의 자체 Canvas
  편집기 중 상황에 맞게 선택해 이어간다(대표님 확정, 2026-09-23).

### 2-B'. 자체 Canvas 편집기 (신규 — 대표님 정정: "캔바"는 Canvas였음)
- 2026-09-23 대표님이 명확히 정정: 이전에 "캔바"로 논의됐던 것은
  Canva(디자인 서비스)가 아니라 **Canvas**(HTML5 편집기, Fabric.js
  등으로 마우스 드래그·리사이즈 지원)를 가리켰음.
- AI가 생성한 배경 이미지 위에 상품 누끼 이미지·텍스트를 레이어로
  올려 마우스로 배치하는 자체 편집기 — 외부 서비스 의존 없음.
- 도입은 단계적으로(배경표시→텍스트오버레이→드래그 가능) 진행 권장,
  Fabric.js 신규 도입 필요(현재 package.json에 없음, grep 확인).

### 2-C. Adobe Firefly/Express 자연스러운 개입점 — 확정된 현실적 방식
**Adobe 공식 커뮤니티 답변으로 확정(2026-09-23)**: Firefly Services
API(서버가 자동 호출하는 방식)는 **Enterprise 계약 전용, 개인
Creative Cloud Premium 구독으로는 발급 불가**. `FIREFLY_SERVICES_
CLIENT_ID/SECRET`가 Vercel에 아예 없음(실측 확인) — 서버 자동화
경로는 현재 막혀있음.

**대표님 확정 방식(2026-09-23, 3단계 예시는 구조 참고용, 그대로
적용 아님)**: Gemini 채팅에서 만든 정확한 프롬프트를 바탕으로,
**"Firefly로 만들기" / "Express에서 편집하기" 버튼**을 자연스러운
개입점에 배치 — 클릭 시:
1. 프롬프트(또는 이미지)를 클립보드에 자동 복사
2. Firefly(firefly.adobe.com) 또는 Express(express.adobe.com) 웹을
   새 창으로 열기
3. "프롬프트가 복사됐어요, 붙여넣기(Ctrl+V)하세요" 안내 토스트
- **정직한 확인 필요 사항**: Firefly 웹이 URL 파라미터로 프롬프트를
  사전 채워주는 공식 기능은 웹검색으로 확인하지 못함(Adobe 공식문서
  helpx.adobe.com에 없음) — 있다면 대표님이 실제로 Firefly에서
  생성 시도 후 주소창을 확인해 알려주시면 정확히 반영, 확인 전까지는
  "클립보드 복사 + 새 창" 방식(100% 확실히 작동)으로 구현.
- 배치 위치는 참고 3단계 예시("호버 시 버튼", "섹션 클릭 시 툴바")
  구조를 힌트로, 실제 UI/UX는 채팅+Canvas 흐름에 맞춰 별도 설계.

## 4. 기존 인프라와의 관계 (재사용 — #295 단일권위)

- 8단계 HTML/PNG 콘텐츠 조립 파이프라인(rev201 근본수정 완료)은
  그대로 유지 — 채팅으로 만든 이미지가 이 파이프라인의 입력(썸네일/
  상세이미지)으로 들어가는 구조.
- `generate-detail` API(#47 재조사에서 발견, 이미 PNG+HTML 완전
  반환)는 여전히 유효 — 채팅 이미지 생성은 이 API가 쓰는 "재료
  이미지"를 준비하는 상류 단계.
- **"배양실"/"관제탑"은 신규 명칭이 아니라 기존 코드에 이미 있는
  정확한 명칭**(md 파일이 "새 제안"처럼 표현했으나 실제로는 기존
  구조와 동일 — 2026-09-23 코드 대조로 확인) — 화면을 갈아엎지 않고
  기존 탭 안에 2x2 갤러리+채팅만 얹는다.
