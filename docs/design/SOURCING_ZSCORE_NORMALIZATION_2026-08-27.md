> 권위: 확정 시 `trend-analyzer.ts`(신호 생성) + `sourcing-lenses.ts`(급상승 판정)의 트렌드 정규화를 override.

## 1. 문제 (프로덕션 DB 실측, 2026-08-27)

`sourcing_opportunity_records` 최근 14일 d1 분포:

| d1 | 추천수 | 비율 |
|---|---|---|
| 스포츠/레저 | 14 | **35%** |
| 패션의류 | 14 | **35%** |
| 디지털/가전 | 5 | 12.5% |
| 생활/건강 | 5 | 12.5% |
| 가구/인테리어 | 2 | 5% |

**2개 대분류가 추천의 70% 독식.** 이 스토어 실제 상품군(생활/주방/인테리어 공산품)과 어긋남 → 새싹셀러가 매일 받는 추천의 70%가 자기 상품군과 무관.

## 2. 근본 원인 (코드 실측)

- `trend-analyzer.ts` `computeRisingRate`: 전반부→후반부 평균 변화율(**절대값**).
- `fetchCategoryTrendSignals`가 `risingRate` **절대값으로 정렬**(133: `sort by b.risingRate`), z-score/percentile **정규화 없음**.
- 결과: 계절·트렌드 변동이 본질적으로 큰 카테고리(스포츠/레저·패션의류)가 risingRate 절대값이 항상 높아 **구조적 상위 독식**. 꾸준한 생활/주방은 변동 작아 밀림.
- → "절대 변화율"은 카테고리 간 **변동성 기저(baseline volatility)가 달라 불공정 비교**.

## 3. 해결 설계 (전 상품 공통·비용0)

### 3-1. z-score 정규화 (핵심)
- 각 카테고리의 risingRate를 **자기 이력 대비** z-score로 변환: `z = (현재risingRate − 그 카테고리 평균) / 그 카테고리 stddev`.
- 의미: "그 카테고리 기준으로 지금이 얼마나 이례적으로 뜨는가" — 절대 변동 크기가 아니라 **상대적 이상치**.
- 효과: 스포츠/레저가 늘 20% 뛰면 z≈0(평소), 생활/주방이 평소 2%인데 지금 8%면 z 高 → **진짜 신호**가 올라옴.
- 데이터: DataLab 시계열(이미 `ratios[]` 보유) 활용 → 추가 API 없음(비용0).

### 3-2. 대분류 라운드로빈 쿼터 (보완)
- z-score 정렬 후에도 한 d1이 슬롯을 독식하지 않게, **LENS_DAILY_QUOTA 배분 시 d1별 상한**(예: 한 d1 최대 40%).
- `allocateByLens`에 d1 다양성 게이트 추가.

### 3-3. 계층 샘플링 (선택)
- d1뿐 아니라 d2 수준에서도 다양성 확보(같은 d1 내 편중 방지).

## 4. 완료 조건 (검증=분포)
- 프로덕션 재측정: 상위 2개 d1 비율이 70% → **≤50%**로 완화, 하위 카테고리(생활/건강·가구/인테리어) 노출 증가.
- 스토어 실제 상품군(생활/주방/인테리어) 추천 비중 상승 확인.
- z-score 도입이 급상승 렌즈의 **진짜 급등**은 여전히 포착하는지(회귀 없음) 골든 시나리오 검증.
- COMPLETION_GATE C1~C6 + /growth 위젯 d1 다양성 브라우저 실측.

## 5. 의존성·범위
- 독립. write set: `trend-analyzer.ts` + `sourcing-lenses.ts`(급상승 판정) + `sourcing-recommender.ts`(allocateByLens d1 게이트). 카테고리 매처(UCE)·발행넛지(F)와 무겹침 → 병렬 안전.
- z-score는 **최소 표본** 필요(카테고리별 이력 6포인트 이상). 표본 부족 시 절대값 폴백(정직표시).

## 6. 개입점·원칙
- 편중 완화는 자동(운영자 개입 불요). 단 "왜 이 추천이 떴나"에 z-score 근거 표시(투명성).
- 정직표시: z-score 계산 불가(표본부족) 카테고리는 그 사실 표시(#310).
- 전 상품 공통: 특정 카테고리 하드코딩 금지, 통계 정규화 레벨만.
