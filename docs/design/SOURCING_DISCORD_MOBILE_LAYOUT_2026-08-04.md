# 소싱봇 Discord 모바일 레이아웃 재설계안 — 설계 초안 (구현 대기)

> 작성일: 2026-08-04 | 작성 컨텍스트: Desktop, 운영자 실발송 스크린샷 피드백 기반
> 상태: **설계만 확정, 코드 미구현** — 다음 세션 착수 대상
> 관련 완료 작업: `docs/research/SOURCING_NEGATIVE_MARGIN_ROOT_CAUSE_2026-08-04.md`(마진 정직화), 커밋 `0470e47`(이종상품 필터), `9734338`(AI코멘트 근본수정)

## 1. 배경

운영자가 실제 모바일 Discord 클라이언트로 발송된 메시지를 스크린샷으로 확인(2026-08-04 19:47 PM 발송분). "디스코드 알림은 모바일로 확인하는 경우가 대부분"이라는 전제 하에 가독성 개선 요청.

## 2. 오늘 완료한 것 (A안, 안전·즉시 반영)

1. AI 인사이트 프롬프트 근본수정 — "대안을 찾으라"는 모순 조언 제거, 키워드별 구체적 실무 팁으로 전환(커밋 `9734338`)
2. 가격 이상치 경고에 이유 명시 — "⚠️ 가격 확인 필요(다른 상품일 수 있어요)"

## 3. 다음 세션 착수 대상 (B안, 레이아웃 재설계)

### 3-1. 현재 구조의 모바일 문제점 (실측)
- Discord 모바일 클라이언트는 필드 폭이 좁아 **줄바꿈이 잦다** — 현재 필드 하나(`field.value`)에 경쟁정보·가격·AI코멘트·도매처 2건까지 5~6줄이 들어가 세로로 매우 길어짐(스크린샷 실측: 필드 하나가 화면의 1/3 이상 차지)
- 순위 이모지(🥇🥈🥉4️⃣5️⃣)와 유형 배지(🏆황금상품)가 제목 줄에 같이 붙어 시각적으로 복잡
- 사용자가 "이 상품이 뭔지 vs 살지말지"를 판단하는 데 필요한 핵심 3가지(가격범위·경쟁도·검색량)가 문단 속에 섞여 있어 스캔이 느림

### 3-2. 제안 방향 (구현 전 운영자 확인 필요)
**옵션 1 — 필드 압축(리스크 낮음)**: AI 코멘트를 인라인에서 제거하고 `description`(embed 상단 요약)에 "오늘의 소싱 전략"으로 한 번만 통합 노출. 개별 상품 필드는 가격·경쟁도·도매처 링크만 남겨 필드당 3~4줄로 축소.

**옵션 2 — Discord embed `fields` inline 활용(리스크 중간)**: 경쟁도·검색량·가격을 `inline:true` 3분할 필드로 나눠 가로 배치 시도. 단, Discord 모바일은 inline 필드도 화면폭에 따라 자동으로 세로 재배치되므로 효과가 제한적일 수 있음 — **사전 실측 필요**(임의 가정 금지, #310 원칙).

**옵션 3 — 요약형 + "더보기 링크"(리스크 낮음, 효과 큰편)**: Discord embed에 상품별 상세 URL을 앱 페이지로 연결(`/sourcing/[keyword]` 신규 라우트 필요)해서, 메시지 자체는 순위·이름·핵심 1줄·링크만 담고 상세(도매처 다건·AI코멘트)는 앱에서 확인하게 분리. 앱 페이지 신규 개발이 필요해 작업량이 가장 큼.

### 3-3. 권장 착수 순서 (Desktop 의견)
1. 먼저 **옵션 1**(가장 안전·빠름)을 다음 세션에 구현해 실제 모바일로 재검증
2. 그래도 부족하면 **옵션 2**를 Discord API 실측(테스트 서버 또는 dry-run 미리보기)으로 검증 후 적용
3. 옵션 3은 별도 기능(앱 상세 페이지)이 필요해 우선순위 낮음 — P3/P4(Kkotti Agent PRD)와 함께 검토

### 3-4. 안전 수칙
- Discord embed 필드 구조를 바꾸는 코드는 **로컬 dry-run으로 실제 embed JSON을 먼저 확인**(curl)한 뒤, 실제 Discord 테스트 채널이 있다면 그쪽으로 먼저 발송해 모바일 실물로 확인 후 프로덕션 채널 반영.
- 이 작업은 `sourcing-recommender.ts`의 `buildSourcingRecommendEmbed()` 단일 파일 수정으로 완결 가능 — write set 겹침 없음(#322), 병렬 작업 안전.
