## 1. 실측 확인된 현재 상태 (환각 없이 코드 기준)

| 표면 | 정보량 | 실측 근거 |
|---|---|---|
| 디스코드 embed | 의도적 압축(모바일 최적화 설계·rev 문서화됨) — 상품당 핵심 3줄(경쟁+검색량, 도매처 1건, 렌즈배지), AI코멘트는 상단 1회 요약 | sourcing-recommender.ts:901~ 주석 명시 |
| 앱 SourcingDetailDrawer | 이미 구현됨: aiInsight, entryBarrier(레벨+점수+보너스), topSellers, 전체 wholesaleMatches, blueOcean 세부점수 | 같은 파일 766줄~ |
| **연결** | **없음** — embed에 앱 링크/버튼 0건, recordId로 앱 진입 라우트 0건 | grep 실측 |

**핵심 통찰**: "정보가 부족한" 게 아니라 "이미 만든 상세 정보로 가는 문이 없는" 문제. 새 기능 개발이 아니라 **다리 하나만 놓으면 되는 저비용 개선**.

## 2. 설계 — 디스코드 → 앱 딥링크 (전 상품 공통)

### 2-1. embed에 앱 딥링크 추가
- 각 상품 필드 또는 embed 하단에 **"앱에서 상세보기"** 링크: `https://kkotium-garden.vercel.app/growth?highlight={recordId}`
- Discord embed는 `url` 필드(임베드 전체 클릭) 또는 하단 텍스트링크 지원 — 모바일 앱에서도 시스템 브라우저/인앱으로 열림.
- 모든 소싱 기회에 recordId가 이미 있으므로(SourcingDetailDrawer 데이터 확인) 전 상품 공통 적용 가능.

### 2-2. 앱 측 진입점 처리
- `/growth?highlight={recordId}` 쿼리 파라미터 수신 → 페이지 로드 시 해당 recordId의 카드로 자동 스크롤 + `drawerItem` 자동 오픈(SourcingDetailDrawer 즉시 표시).
- 워크플로 완결: 디스코드 알림 확인 → 클릭 → 앱에서 바로 상세(진입 마찰 0).

### 2-3. "정보 확장" 원칙 (전 상품 공통 체크)
- 디스코드 압축은 **의도된 설계**(모바일 가독성) — 유지. 되돌리지 않음.
- 앱 쪽엔 압축 없이 **모든 필드 노출**: aiInsight 전문, 렌즈 판정 근거, wholesaleMatches 전체 목록(디스코드는 1건만), entryBarrier 세부 점수 breakdown.
- 카탈로그 상품 수 무관 — recordId 기반이라 몇 건이 오든 동일 동작(#352 전상품 검증 원칙).

## 3. "최신 정보로 업데이트되고 있나" — 병행 확인 필요
대표님 지시대로 "최신 정보 제대로 반영" 재확인 대상(별도 검증 필요, 이 설계 범위 밖 표기):
- 소싱 렌즈 판정 근거(z-score·트렌드)가 카테고리 마스터(현재 갱신 대기 중)에 의존하는지 확인 필요.
- 카테고리 마스터 갱신(대표님 XLS 대기) 완료 후, 소싱 추천의 카테고리 라벨도 함께 재검증 권고(연쇄 영향).

## 4. 완료 조건
- 디스코드 embed에 앱 링크 추가 → 실제 클릭 시 `/growth?highlight=` 정상 라우팅 브라우저 실측.
- 카탈로그 밖 임의 recordId로도 자동 오픈 확인(하드코딩 없음).
- 디스코드 실발송 없이(크론 수동실행 금지) 오프라인/dryRun으로 embed 구조만 검증.
