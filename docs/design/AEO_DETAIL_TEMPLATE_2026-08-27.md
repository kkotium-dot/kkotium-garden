- **판매실적 기반 재편**: 13개월 미판매 판매중지, 등록한도 실적연동. AEO는 "노출→전환" 실적으로 이어져야 의미.(etnews 2026-04)

## 3. 강화 설계 (전 상품 범용)

### 3-1. 프롬프트 강화 (route.ts buildAEOPrompt)
- Answer-first 규칙 추가: "각 답변은 첫 문장에 결론, 이후 근거."
- 스펙표 섹션 추가: `specTable: [{label, value}]` — 상품 attributes에서 자동 생성(없는 값 생략, 지어내기 금지).
- 정량 지시 강화 + 정책 가드(과장·허위 스펙 금지).
- 질문은 네이버 실제 검색 패턴(용도·비교·관리·호환) — 이미 있음, 유지.

### 3-2. 전 상품 범용 보장
- 입력이 빈약한 상품(속성 적음)도 안전: 있는 데이터만으로 생성, 없으면 해당 Q&A/표행 생략(빈손 정직).
- 상품군 하드코딩 0 — 주방·디지털·인테리어·패션 무관 동일 파이프라인.
- category는 UCE 결과(정답률100%) 연동 → 정확 카테고리 문맥이 AEO 품질↑(시너지).

### 3-3. 개입점 (자연스러운 녹임)
- 씨앗심기/상세 아틀리에에서 "AEO 강화 생성" 액션 → 결과 미리보기·편집(운영자 승인 후 반영).
- 생성 결과에 "정책 안전"(과장 없음) 체크 표시.

## 4. 완료 조건 (검증)
- 임의 상품 10종(카탈로그 밖 포함)으로 aeo-generate 실호출 → Answer-first·스펙표·정량 수치 확인, 없는 속성 안 지어냄(정직).
- 정책 위반 문구(과장·허위) 미생성 확인.
- 전 상품 범용: 속성 빈약 상품도 크래시 없이 축약 생성.
- COMPLETION_GATE C1~C6 + 씨앗심기 UI AEO 미리보기 브라우저 실측.

## 5. 의존성·범위
- 독립. write set: `aeo-generate/route.ts`(프롬프트·응답스키마) + 상세 UI(미리보기). 소싱·z-score·F와 무겹침 → 병렬 안전.
- UCE와 시너지(의존 아님): 정확 category가 AEO 문맥 품질↑.
- 비용: Groq 1회/상품(기존과 동일), 추가 API 없음.

## 6. 우선순위 메모
- 새싹셀러 레버 순서: 발행수↑ > 상품명SEO > 리뷰 > **AEO 상세**(상품 살아있고 트래픽 생긴 뒤 효과). AEO는 "지금 당장 매출"보다 "AI 검색 시대 대비" — z-score/F 다음 순위가 맞음.
