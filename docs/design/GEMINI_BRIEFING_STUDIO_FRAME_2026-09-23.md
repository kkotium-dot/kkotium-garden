# 제미나이 전달용 브리핑 — 꽃단장 작업실(Studio) 단계별 프레임 시안 요청

작성: 2026-09-23(재작성 — 1차 초안이 4단계를 뭉뚱그려 설명해 대표님이
정확히 지적: 각 단계는 서로 다른 작업이므로 단계별로 각각 다르게
설명해야 제미나이가 정확한 섹션별 시안을 만들 수 있음).

목적: 제미나이가 Canvas로 섹션 구조·비율·기능 배치를 시각화할 때,
실제 앱의 4단계 각각이 정확히 무슨 작업 화면인지 구분해 전달.

---

## 0. 전체 공통사항 (4단계 모두 동일 적용)

**확정된 브랜드컬러**(`docs/design/KKOTIUM_DESIGN_SYSTEM.md` 기준):
UI 화면에는 로고 팔레트(레드 `#E62310` + 핑크 `#FFCCEA`)만 사용,
캐릭터 팔레트(레드+그린+블랙)는 마케팅 비주얼 전용이라 이번 UI
작업엔 안 씀. 베이스는 화이트/라이트그레이 위주(75~80%).

**공통 골격**: 상단에 4개 탭(1.썸네일 랩 → 2.상세 캔버스 → 3.SEO
부스터 → 4.발행 검토)이 있고, 그 아래가 3단 그리드(좌측 도구/사이드바
20% · 중앙 작업영역 55% · 우측 진단패널 25%)입니다. 좌측 사이드바는
4단계 내내 고정(창고/배양실/일지 탭 전환용), **중앙과 우측의 내용만
탭마다 완전히 바뀝니다.**

**기술 제약**: Tailwind 클래스가 아니라 인라인 style 또는 CSS 변수
(`var(--gp-*)`) 기반 코드 관례를 따를 것. JSX 안에 이모지 금지
(Lucide React 아이콘만). 주석은 영어. 다크 테마 아님 — 라이트
(핑크/크림/화이트) 톤 유지.

## 1. Step "썸네일 랩" — 목적: 대표 이미지 1장을 만드는 화면

**정확한 작업 목적**: 셀러가 상품의 메인 썸네일(네이버 검색결과에
노출되는 1000x1000 정사각 이미지)을 만든다. 원본 소스 이미지를
고르고, AI로 배경/합성을 만들고, 여러 후보 중 하나를 "대표 이미지"로
확정하는 게 이 화면의 유일한 목표.

**이미 있는 기능(재사용, 새로 제안하지 말 것)**:
- `ThumbnailCard` — 메인 카드. 소스 이미지 드롭존, AI 생성 큐
  (진행 단계 표시), Firefly 프롬프트 빌더(6요소 자동합성 → 클립보드
  복사 → firefly.adobe.com 새창 열기, **실제 API 자동화 아님**),
  생성 결과 재업로드.
- `DiagnosisCard`(접힘 패널) — 이미지 품질 진단(워터마크·해상도 등).
- `MoodCameraPanel`(접힘 패널) — 무드/카메라 앵글 프리셋.

**이번에 새로 필요한 것**:
- **인앱 Gemini 채팅** — 지금은 6요소를 폼으로 하나씩 입력하는데,
  이걸 "대화로 다듬기"로 보강. 완전 교체가 아니라 기존 폼 위/옆에
  추가.
- **2x2 이미지 후보 그리드 + 대표 이미지 자동 선택** — 여러 장이
  생성됐을 때 나란히 비교하고 클릭 한 번으로 "대표"를 정하는 UI
  (현재는 목록형 나열만 있음).
- Adobe Firefly 버튼의 배치를 더 자연스럽게(현재는 접힌 상세보기
  안에 있어 눈에 잘 안 띔).

**우측 패널에 필요한 것**: 이 단계에서는 "1000x1000 정사각 규격
충족 여부"만 보여주면 충분 — SEO 텍스트 진단은 3단계 전용이라 여기
넣지 않음.

## 2. Step "상세 캔버스" — 목적: 상세페이지 전체를 조립하는 화면

**정확한 작업 목적**: 1단계에서 만든 이미지들과 상품 정보를 조합해,
네이버 스토어에 올릴 상세페이지(세로로 긴 여러 섹션: 히어로 →
문제공감 → 강점 → 스펙 → 후기 → 배송안내 → 구매유도)를 완성한다.
1단계가 "이미지 1장"이라면, 2단계는 "이미지+텍스트로 된 긴 페이지
전체".

**이미 있는 기능(재사용)**:
- `DetailPageCard` — 상세페이지 생성 트리거+결과 미리보기.
- `SlotFunnelBoard`(접힘 패널) — 각 섹션 슬롯의 진행 상태.
- `DetailAssemblyBoard`(622줄, 완성된 핵심 기능) — 섹션별로 어떤
  이미지를 배정할지 클릭으로 지정, 자동저장. **이게 이 단계의 진짜
  핵심 작업 도구인데 지금 화면에서 존재감이 약함 — 더 눈에 띄게
  배치할 필요.**

**이번에 새로 필요한 것**:
- 대표님이 앱 안에서 채팅으로 완성한 "HTML 상세페이지"와 "자체
  Canvas(레이어 편집기, Fabric.js 등)" 두 가지 방식 중 상황에 맞게
  선택할 수 있는 진입점.
- Adobe Firefly "배경 확장"(섹션 이미지 연결부가 부자연스러울 때),
  Adobe Express "정밀 보정" 버튼의 자연스러운 위치(예: 섹션 이미지에
  마우스를 올렸을 때, 또는 섹션 사이 구분선 클릭 시).

**우측 패널에 필요한 것**: 세로로 긴 상세페이지가 네이버 규격
(가로 860px 등)에 맞는지, Alt 태그가 채워졌는지 등 — 1단계와는
다른 체크리스트.

## 3. Step "SEO 부스터" — 목적: 텍스트(카피)를 검색에 맞게 다듬는 화면

**정확한 작업 목적**: 이미지가 아니라 **텍스트**가 대상. 상품명,
키워드, 카테고리 매칭도(DNA), 훅 문구가 네이버 검색 알고리즘에
얼마나 잘 맞는지 진단하고 고친다. 1·2단계가 "만들기"라면, 3단계는
"검수하고 다듬기"에 가까움.

**이미 있는 기능(재사용)**:
- `CategoryDnaCard` — 카테고리 매칭도 진단(있어야 할 키워드가
  실제로 상품명에 있는지 DNA 비교).

**이번에 새로 필요한 것**: 이 브리핑 요청 시점에는 구체적 신규 요구
없음 — 다만 화면이 진단 카드 하나뿐이라 휑해 보일 수 있어, 레이아웃
비율 조정이 필요할 수 있음(중앙 영역을 더 좁히고 진단 항목을 더
크게 보여주는 방향 등 자유 제안 환영).

**우측 패널에 필요한 것**: 신호등(초록/노랑/빨강) 시스템으로
"이 키워드는 검색량이 있다/없다", "경쟁 강도" 같은 항목을 한눈에.

---

## 4. Step "발행 검토" — 목적: 네이버에 올리기 직전 마지막 확인 화면

**정확한 작업 목적**: 지금까지 만든 모든 걸 최종 점검하고 실제
네이버 스토어에 발행(등록)하는 화면. 가장 신중해야 하는 단계 —
발행은 되돌리기 어려운 작업이라 "확실히 준비됐는지" 확인하는 게
전부.

**이미 있는 기능(재사용)**:
- `PrePublishGatePanel` — 발행 전 필수 항목(이미지 규격, 정보고시,
  배송정책 등) 체크리스트, 미비 시 발행 차단.

**이번에 새로 필요한 것**: 이 브리핑 요청 시점에는 구체적 신규 요구
없음 — 체크리스트가 명확하고 신뢰감 있게 보이도록, 그리고 "이래서
발행이 막혔다"는 이유가 한눈에 보이는 레이아웃 제안 환영.

**우측 패널에 필요한 것**: 없음(또는 최종 요약만) — 이 단계는 중앙의
체크리스트 자체가 핵심이라 우측 패널 비중을 줄이는 것도 고려할 만함.

## 5. 정확히 요청하는 산출물

**4단계 각각을 별도 섹션으로 나눠서** 시안 코드를 요청합니다.
"Studio 전체 화면 1개"가 아니라, "1단계 화면", "2단계 화면", "3단계
화면", "4단계 화면"을 각각 독립적으로 제안해주세요 — 각 단계가 정확히
다른 목적(이미지 1장 만들기 / 페이지 전체 조립 / 텍스트 다듬기 /
최종 점검)이므로 레이아웃 비율과 강조점도 단계마다 달라야 합니다.
