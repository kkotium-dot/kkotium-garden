## 롱네임(실제 상품명) 케이스 — B3 검증 중 목격
실제 크롤 상품명 "32구 2단 원터치 아이스 트레이 64구 얼음 보관함"의
크롤 화면 카테고리 자동추천 1순위가 **"패션잡화>주얼리>주얼리소품>
보관함/케이스"**였다(2순위가 정답 "생활/건강>주방용품>보관/밀폐용기").
→ 단독 "아이스트레이"는 정답인데, 긴 상품명에 "보관함"이 섞이자
"주얼리 보관함"에 낚였다. **롱네임의 복합 신호 처리 문제** — 여러 명사가
섞일 때 헤드노운 판정이 흔들린다.

## 세 갈래 근본원인 가설 (미검증 — Code가 확정 필요)

### A. 트레일링 "이" 스트리핑 (넥타이 vs 목걸이)
- `extractNouns`(morpheme-tokenizer.ts)가 "넥타이"의 트레일링 "이"를
  조사로 오인해 "넥타" 로 스트리핑 → headNoun≠"넥타이" → d3 정확매칭 실패
  가설(UCE-10 커밋 메시지에 기재).
- **그러나 "목걸이"는 정답** → 스트리핑이 무조건은 아님. 차이의 원인을
  Code가 tokenizer 실행으로 확인해야 함(복합명사 사전 등재 여부? "목걸이"는
  COMPOUND_NOUNS에 있고 "넥타이"는 없을 가능성).

### B. 동음이의 리프 충돌 (우산)
- 골프필드용품>우산(골프우산)이 실재 d4라 패션잡화>패션소품>우산과
  Tier1 완전일치가 양쪽 발화. UCE-10 결함C(동점보너스)와 다른 종류 —
  "같은 리프명이 서로 다른 카테고리에 정당하게 실재"하는 경우의 우선순위.
- 해결 난이도 높음(문맥 없이는 어느 쪽이 정답인지 알 수 없음). 롱네임이면
  주변 명사로 구분 가능하나 단독명은 사람 확인(UCE-4 개입큐)이 정답일 수도.

### C. 부분 substring 오낚임 (얼음트레이→전기밥솥, 토마토고블렛→토마토)
- "얼음트레이"에서 "트레이"가 아니라 다른 부분이 전기밥솥 리프의
  slash-packed synonym에 걸렸을 가능성. "토마토고블렛"은 "토마토"가
  식품 리프에 완전일치로 낚임(고블렛=유리잔이 헤드노운이어야 함).
- UCE-9 계열(부분매칭 오낚임)의 잔여 케이스로 보임.

## Code 착수 시 권장 절차 (#352 준수)
1. `extractNouns("넥타이")` vs `extractNouns("목걸이")` 직접 실행해 A 확정
2. 카탈로그 밖 "~이"로 끝나는 상품명 20종 + "트레이/고블렛" 복합명사
   20종 전수 dryRun으로 영향 범위 측정(전 상품 공통 관점 #62)
3. 롱네임 복합신호: 실제 크롤 상품명 형태(수식어+핵심+부가설명)로
   테스트 — 헤드노운 판정이 마지막 명사에 쏠리는지 확인
4. 수정 후 test:category-match/integrity 회귀 0 + 캐시버전 증가(#351)

## 우선순위 판단
- **A(트레일링 이)가 최우선** — "~이"로 끝나는 상품명은 흔하고(목걸이·
  줄넘기·손잡이 등), 전 상품 공통 영향. 단 "목걸이"가 정답인 걸 보면
  이미 부분적으로 처리돼 있어 영향 범위 측정이 먼저.
- C(부분 substring)는 UCE-9 계열 연장이라 기존 방어 로직 확장으로 가능.
- B(동음이의)는 근본해결이 어려워 UCE-4 개입큐(사람 확인)로 흘리는 게
  현실적일 수 있음 — 무리한 자동화보다 정직한 "확인 필요"가 나음(#353).
