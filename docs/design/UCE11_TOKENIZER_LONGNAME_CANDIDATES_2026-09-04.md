## 결함A 확정·수정 완료 (2026-09-04, Code)

`extractNouns()` 직접 실행으로 가설 A를 실측 확정했다:
```
넥타이 => {"nouns":["넥타"]}   ← 스트리핑됨
목걸이 => {"nouns":["목걸이"]}  ← COMPOUND_NOUNS의 '걸이' 부분매치로 우연히 보호
```
카탈로그 밖 "~이" 어미 20종 dryRun 결과, 20종 중 실제 스트리핑 피해는
표준어·고빈도 상품 식별자 6종으로 좁혀졌다(나머지는 이미 걸이/꽂이로
보호되거나, 마스터에 아예 없는 리프라 스트리핑과 무관하게 no-match).
`identity-dictionary.ts`의 COMPOUND_NOUNS에 **넥타이·손잡이·재떨이·
손톱깎이·딸랑이·지팡이** 6종을 추가(#353 고신뢰만 자동 — 나머지 후보는
표준어/빈도 확신 부족으로 보류, 아래 "보류 후보" 참조).

**중요 정정**: 애초 headNounWeight의 부분포함 관용성(`p.includes(term) ||
term.includes(p)`) 때문에 "넥타"→"넥타이" 보호가 넥타이 자체의 오분류엔
영향 없을 것으로 예상했으나, **실측(test:category-match)은 반대**였다 —
COMPOUND_NOUNS 등재 후 "넥타이"가 출산/육아>유아동잡화(오답)에서
패션잡화>패션소품(정답)으로 실제 전환됐다. 손트레이스만으로 매처 결과를
예단하지 말 것(#350 표면신호 재검증과 같은 교훈) — 반드시 실행해 확정.

**얼음트레이 계열(결함C)은 결함A와 무관함을 실측으로 반증**: "얼음트레이"가
디지털/가전>주방가전>전기밥솥으로 낚이는 원인은 매처가 원본 `name`(스트리핑
안 된 원문)을 haystack으로도 쓰기 때문에, 트레일링-이 스트리핑 여부와
무관하게 "트레이" 3글자가 전기밥솥 리프의 슬래시패킹 라벨("내솥/패킹/
트레이")과 그대로 부분매칭된다. 정답 브랜치(생활/건강>주방용품>보관/밀폐
용기)엔 "아이스트레이"라는 구체 d4는 있어도 범용 "트레이" 리프가 없어
경쟁 후보가 없는 게 근본 원인 — **결함C는 결함A 수정으로 해소되지 않는
별개 사안**이다. 아래 "보류 후보"에 후속 티켓으로 남긴다.

**보류 후보(이번 세션 미수정, 후속 검토 필요)**:
- 결함C(부분 substring 오낚임) — "얼음/다용도/화장품/주방/서빙트레이" 5/10종이
  여전히 전기밥솥으로 오분류(트레이/고블렛 20종 dryRun 실측). 고블렛 10종은

### 결함C 정확한 트리거 규명 (2026-09-05, Desktop 실측)
프로덕션 API 재실측: "얼음/서빙/다용도/주방/화장품/정리트레이" **6/6 전부**
`디지털/가전>주방가전>전기밥솥`으로 오분류(계열 전면 결함, "~트레이" 흔한
생활잡화라 파급 큼). 로컬 매처 스코어 실행으로 근본 트리거 확정:
```
얼음트레이 => [디지털/가전>주방가전>전기밥솥>내솥/패킹/트레이  tier1 score20.00]  (유일 후보)
아이스트레이 => [보관/밀폐용기>아이스트레이 score195] > [아이/넥케어 30] > [내솥/패킹/트레이 20]
```
- `termMatchScore`가 slash-packed 라벨 "내솥/패킹/트레이"를 splitSynonyms로
  쪼개 "트레이"(3자) 부분매칭 → partial coverage 0.5배 → **정확히 20.00점**.
- 정답 리프 "아이스트레이"는 "얼음트레이"와 substring 불일치라 **후보에조차
  안 올라** 경쟁자 없음 → 20점 단독 1위로 확정.
- **진짜 트리거**: `category-ai-suggest.ts`의 `isDeterministicLowConfidence`가
  `top.score < DETERMINISTIC_MIN_CONFIDENT_SCORE(=20)`로 판정하는데 점수가
  **정확히 20** → `20 < 20 == false` → 저신뢰로 안 잡힘 → AI 교차확인/
  개입큐를 그대로 통과. 경계 하나(`<` vs `<=`) 차이로 명백한 오답이 확정됨.

**수정 방향 2안(Code가 #352 dryRun으로 택일)**:
- (a) 경계 완화: `< 20` → `<= 20`(또는 임계 상향). 최소 변경이나, 정상적으로
  20점을 받는 다른 케이스(짧은 정답 리프)가 불필요하게 AI로 넘어가 비용↑
  가능 — 20점 전후 분포를 dryRun으로 측정 후 결정.
- (b) 근본 수정: splitSynonyms partial 매칭이 **파편 1개만**(예: 3종 중 "트레이"
  하나) 걸릴 때 페널티를 더 강화(현재 0.5배 → 더 낮추거나, 물건종류 generic
  명사 파편은 신호에서 제외). "트레이/쟁반/받침" 같은 범용 물건종류어가
  엉뚱한 상위카테고리 slash-라벨에 낚이는 UCE-9 계열 전반에 효과.
- 권장: (b)가 전 상품 공통(#62)에 부합하나 회귀위험 크므로, **(a)+(b) 병행**
  — (a)로 즉시 안전망(저신뢰→AI/개입큐), (b)로 근본 억제. 둘 다 카탈로그밖
  "~트레이/~받침/~쟁반/~정리함" 30종+ 전수 dryRun 회귀0 확인 후 적용,
  CATEGORY_MATCH_LOGIC_VERSION 3→4(#351).
- 결함B(동음이의) — "우산"은 여전히 스포츠/레저>골프로 매칭(정당한 리프
  충돌, 자동 해결 난이도 높음 — 기존 판단 유지, UCE-4 개입큐 후보).
- 다듬이·부지깽이(희귀/구식 확신 부족)·쓰레받이(표준어 아님 — 정식은
  "쓰레받기")·화분받이·냄비받이(정식은 "화분받침"/"냄비받침", -침으로
  끝나 이 버그 영향 밖) — COMPOUND_NOUNS 미등재로 보류.

## 세 갈래 근본원인 가설 (미검증 — Code가 확정 필요)

### A. 트레일링 "이" 스트리핑 (넥타이 vs 목걸이)
- `extractNouns`(morpheme-tokenizer.ts)가 "넥타이"의 트레일링 "이"를
  조사로 오인해 "넥타" 로 스트리핑 → headNoun≠"넥타이" → d3 정확매칭 실패
  가설(UCE-10 커밋 메시지에 기재).
- **그러나 "목걸이"는 정답** → 스트리핑이 무조건은 아님. 차이의 원인을
  Code가 tokenizer 실행으로 확인해야 함(복합명사 사전 등재 여부? "목걸이"는
  COMPOUND_NOUNS에 있고 "넥타이"는 없을 가능성).

### B. 동음이의 리프 충돌 (우산)
- 골프필드용품>우산(골프우산)이 실재 d4라 패션잡화>패션소품>우산과
  Tier1 완전일치가 양쪽 발화. UCE-10 결함C(동점보너스)와 다른 종류 —
  "같은 리프명이 서로 다른 카테고리에 정당하게 실재"하는 경우의 우선순위.
- 해결 난이도 높음(문맥 없이는 어느 쪽이 정답인지 알 수 없음). 롱네임이면
  주변 명사로 구분 가능하나 단독명은 사람 확인(UCE-4 개입큐)이 정답일 수도.

### C. 부분 substring 오낚임 (얼음트레이→전기밥솥, 토마토고블렛→토마토)
- "얼음트레이"에서 "트레이"가 아니라 다른 부분이 전기밥솥 리프의
  slash-packed synonym에 걸렸을 가능성. "토마토고블렛"은 "토마토"가
  식품 리프에 완전일치로 낚임(고블렛=유리잔이 헤드노운이어야 함).
- UCE-9 계열(부분매칭 오낚임)의 잔여 케이스로 보임.

## [2026-09-05 갱신] 결함C 수정 완료 + 결함D 신규 발견

### 결함C — 완료 (커밋 597473c, main 병합·배포)
"~트레이" 6종(얼음/서빙/다용도/주방/화장품/정리) 전기밥솥 오분류를
(a)경계 `<`→`<=` + (b)termMatchScore partial coverage flat×0.5 →
matched/parts 비율로 근본수정. "얼음트레이" 20.00→15.00 하락, 전부
저신뢰(lowConf=true)로 흘러 AI/개입큐 확인 경로 진입. 
검증: test:category-match 33/33, integrity 29/29, tsc0.
Desktop 독립 재검증(#352): 결함C 6종 lowConf=true 전환 + 정답 12종
(아이스트레이195·쟁반·냄비받침135·화분받침120·소품정리함165·넥타이·
목걸이·우산꽂이·디퓨저·아로마방향제) 회귀0 확인.

### 결함D — 신규 발견 (미수정, 후속 티켓) — 복합어 미분리 오낚임
**증상(실측)**: 결함C 수정 후에도 아래는 여전히 오분류, 게다가
**확신구간(lowConf=false)이라 AI 교차확인도 안 거침** — 결함C보다 위험:
```
실리콘트레이 -> 생활/건강>공구>접착용품 [105.0] lowConf=false
미니트레이   -> 스포츠/레저>골프>골프의류 [75.0]  lowConf=false
큐브트레이   -> 출산/육아>완구/인형>유아동퍼즐 [45.0] lowConf=false
```
**근본원인(가설)**: 토크나이저(morpheme-tokenizer.ts extractNouns)가
"실리콘트레이" 같은 복합어를 안 쪼개 **전체어가 headNoun**이 됨 →
"실리콘트레이"의 substring인 짧은 리프(예: 접착용품 계열 slash라벨의
"실리콘" 파편)가 headNounWeight의 `term.includes(p)` 관용매칭으로
HEAD_NOUN_BOOST(3배)를 받아 105점 고득점. 결함C(splitSynonyms 파편
매칭)와 **다른 경로** — splitSynonyms 페널티로는 안 잡힘.

**왜 결함C보다 위험한가**: 15점(저신뢰)이 아니라 105점(확신)이라
