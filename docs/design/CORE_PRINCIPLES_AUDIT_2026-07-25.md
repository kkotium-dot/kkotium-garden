## 2. ★ 추가 권장 2건 (사고 근거 확실 + CORE 공백)

> 아래는 **권장**이며, CORE 수정은 이 audit 범위 밖(audit 모드). 운영자 승인 후 별도 update.

### 후보 A — #296 발행여부 분리는 lifecycle 파생
- **사고**: 2026-07-23 좀비 부활소가 미발행 상품 2건 노출(발행여부 분리가 부활소까지 전파 안 됨).
- **CORE 공백**: §3(판정 단일함수)에 #295는 있으나, "**분류/카테고리(발행여부 포함)도 단일 파생함수로 수렴**"이라는 각론이 없다. #9는 배지·필터·버튼을 말하지 분류축을 명시 안 함.
- **권장 삽입 위치**: CORE §3 #9 아래 또는 §4 #13 보강.
- **권장 문구(초안)**: "발행여부(정원창고↔꽃밭돌보기) 같은 **분류축도 lifecycle 파생**이어야 한다. 화면별 자체 판정하면 부활소에 미발행이 새는 식으로 경계가 뚫린다(#296)."

### 후보 B — #88 완료=검증(Code 보고만으로 완료 금지)
- **사고**: Code 보고를 검증으로 오인(#45 결합). Cowork/Desktop이 Code의 "완료" 라벨을 실측 없이 수용하면 거짓 완료가 트래커에 박힌다.
- **CORE 공백**: §5는 localhost/push/새로고침(#305·#306·#308)을 말하나, "**한 레인의 보고를 다른 레인이 실측 없이 완료 처리 금지**"라는 레인 간 규칙이 없다. §8(협업)에도 없음.
- **권장 삽입 위치**: CORE §5 #16 위 또는 §8 #31 옆.
- **권장 문구(초안)**: "다른 레인의 '완료' 보고는 검증이 아니다(#88). 실측 통과 전까지 '검증 대기'로 둔다. Desktop 실측·프로덕션 확인 전 종결 금지."
