# "오늘의 소싱" 웹앱 심화화면 설계 초안 (2026-08-04)

> 작성 컨텍스트: Desktop, 운영자 요청("Discord=간단 알림, 웹앱=심화 작업공간") 기반
> 상태: **설계 확정 대기(운영자 검토 필요) — 코드 미구현**
> 전제: 이 문서 작성 전 시스템 레벨 전수조사 완료(아래 §1)

## 1. 오늘 전수조사로 확정된 사실 (추측 없음, 전부 실측)

### 1-1. 이미 존재하는 것
- `/growth`("성장·소싱") 페이지가 **이미 정확한 위치**. `SourcingRecommendWidget`이 이미 붙어있음.
- **긴급 버그 발견·수정 완료**(이번 세션): 위젯이 이번 세션에 폐기된 필드(`estimatedMargin`·`avgPrice` 등)를 참조해 전 상품에 빨간 "0%" 마진 배지가 뜨고 있었음 — 근본수정·배포·프로덕션 검증 완료(커밋 `05fa9ca`).

### 1-2. 시스템 레벨 전수조사 결과 (SE05 죽은 API 사용처)
| 파일 | 상태 | 근거 |
|---|---|---|
| `SourcingRecommendWidget.tsx` | 🔴→✅ 수정완료 | 이번 세션 근본수정 |
| `MarketAnalysisCard.tsx`(상품편집 사이드패널) | 🟢 안전 | `if(totalResults===0 && avgPrice===0) return null` 방어 있음 — 섹션이 조용히 안 보일 뿐 |
| `CompetitionMonitorWidget.tsx`(`/market`) | 🟢 안전 | 프로덕션 실측: "0/2" 정직 표시, 가격배지 조건부(`{s && ...}`)라 미노출 |
| `MarketTrendWidget.tsx`(`/market`) | 🟢 안전 | 동일 방어 패턴 |

**결론**: 소싱 위젯만 위험했고 해결됨. 나머지는 "기능이 죽어서 안 보임" 수준(버그 아님, 급하지 않음).

### 1-3. 구조적 한계 (심화화면 설계 전 반드시 풀어야 함)
1. **`daily_recommendations` DB 테이블이 얕음** — 컬럼: `id, date, product_name, supplier_id, honey_score, season_tag, status, created_at`뿐. 가격·경쟁도·도매처 링크를 저장할 곳이 없음. in-memory 5분 캐시가 만료되면 이 얕은 DB로 폴백돼 검색량·경쟁도까지 사라짐(실측: `reason:'db-cached'` 응답에서 전부 0/빈값).
2. **"스캔 시작" 버튼이 `discord:true` 고정** — `SourcingRecommendWidget.tsx`의 `runScan()`이 `body: JSON.stringify({ discord: true })`로 하드코딩. 즉 웹앱에서 새로고침 삼아 눌러도 실제 Discord 채널에 알림이 나감. 웹 스캔과 Discord 발송은 분리돼야 함.
3. **`CompetitionMonitorWidget`의 스냅샷 저장소가 in-memory Map** — 서버리스 환경(Vercel)에서 재배포·재시작마다 소실. 영속화 안 됨.

## 2. 대표님 요청 원문 요약

> Discord = 간단히 한눈에(이미 완성). 웹앱 = 오늘의 소싱 추천을 더 심도있게 — 대응(대체) 상품 등 실무적으로 쓰기 좋게, "제가 일일이 해야 할 작업들의 자동화·간소화"

핵심 키워드: **① 상세 분석 ② 대응(대체) 상품 ③ 반복작업 자동화**

## 3. 설계 방향 (3개 트랙, 우선순위 순)

### 트랙 A — 데이터 영속화 (선행 필수, 다른 트랙의 기반)
**문제**: 지금은 5분 캐시가 전부라 "오늘 아침 추천이 뭐였지" 확인이 안 됨.
**해결**: `daily_recommendations` 테이블 확장 또는 신규 테이블(`sourcing_opportunities`) 신설.
- 저장 대상: keyword, category, monthlySearchVolume, competition, blueOceanScore, supplyPriceRange(min/max), wholesaleMatches(JSON — platform/name/price/url/priceOutlier), aiInsight, recoType, date
- 목적: 캐시 만료와 무관하게 "오늘자 추천"을 항상 완전한 형태로 재구성 가능하게 함
- 부수효과: 과거 추천 이력 조회(예: "지난주엔 뭘 추천했었지") 가능해짐 → 트렌드 파악에 활용 가능

### 트랙 B — 심화 화면 UI (`/growth` 확장)
현재 `SourcingRecommendWidget`(작은 카드형)을 넘어서는 **전용 상세 뷰**가 필요. 두 가지 안:

**안 1 — 위젯 내 "상세보기" 모달/드로어(리스크 낮음, 빠름)**
- 각 추천 카드 클릭 시 우측 드로어(패널)로 상세 열림 — 기존 패턴(상품 편집 사이드패널)과 UI 일관성
- 드로어 안에 담을 내용:
  - 키워드·경쟁도·검색량·블루오션 점수 breakdown(진입장벽 등)
  - **도매매칭 전체 목록**(현재 최대 4건까지 API가 주는데 위젯엔 일부만 노출 — 드로어에선 전부)
  - **priceOutlier 경고가 있는 항목은 "왜 의심되는지" 설명**(가격이 중앙값 대비 크게 벗어남)
  - AI 인사이트 전문
  - **"이 키워드로 상품 등록 시작하기" 버튼** → `/products/new`(씨앗심기)로 딥링크, 키워드 프리필

**안 2 — 전용 페이지(`/growth/sourcing/[date]` 또는 `/sourcing`)(리스크 중간, 더 풍부)**
- 오늘/과거 추천을 날짜별로 넘겨보는 아카이브 뷰
- 트랙 A(DB 영속화)가 선행되어야 의미 있음
- 대표님 언급 "대응 상품"에 가장 잘 맞는 형태: 추천 키워드별로 도매매칭 여러 건을 **비교 테이블**로(가격순 정렬, outlier 필터링 토글)

**권장**: 안 1을 먼저 구현(빠르고 안전), 사용성 확인 후 트래픽/니즈 보고 안 2로 확장.

### 트랙 C — 실무 자동화 (대표님이 가장 강조하신 부분)
"일일이 해야 할 작업의 자동화"에 대한 구체적 제안:

1. **"이 키워드로 소싱 시작" 원클릭** — 추천 카드에서 바로 도매매칭 상품을 골라 `/products/new`(씨앗심기)에 상품명·이미지·공급가를 프리필해서 넘김. 지금은 "도매꾹 검색" 버튼으로 외부 사이트를 열어야 하는데, 이러면 대표님이 직접 상품명·가격을 타이핑해야 함 — 이 타이핑을 없애는 게 핵심 자동화 지점.
2. **"낙점" 상태 관리** — 추천 카드에 "관심 없음"/"검토중"/"소싱 시작함" 상태를 저장해, 다음날 같은 키워드가 또 추천되면 중복 검토를 건너뛸 수 있게. (트랙 A의 DB 확장에 `status` 컬럼 추가로 구현 가능)
3. **주간 요약** — "이번 주 추천 키워드 중 실제로 소싱 시작한 비율" 같은 자기 피드백 지표. 소싱 시스템이 실제로 도움이 되는지 대표님이 판단할 수 있는 근거.

## 4. 구현 순서 제안 (다음 세션)

```
1. 트랙 A(DB 스키마 확장) — 가장 먼저, 다른 모든 것의 기반
2. daily 크론이 저장하는 로직을 새 스키마로 업데이트
3. 트랙 B 안1(상세 드로어) 구현
4. 트랙 C-1(원클릭 소싱 시작) 구현 — 가장 체감 효과 큼
5. "스캔 시작" 버튼의 discord:true 고정 문제 분리(웹 스캔=discord:false 기본)
6. 트랙 C-2(상태 관리), C-3(주간 요약)은 이후 순차
```

## 5. 안전 수칙
- DB 스키마 변경은 `Supabase:apply_migration` 사용, 기존 데이터 손실 없이 컬럼 추가만(테이블 재생성 금지)
- 새 API 라우트는 dry-run 우선 검증 후 실제 저장 로직 연결
- "원클릭 소싱 시작"은 씨앗심기 화면에 값만 프리필하는 것이지, 자동으로 상품을 생성·발행하지 않음(#307 — 발행은 항상 사람 검수 필수, 자동 발행 영구 금지 #307)
