### 파급 3곳

1. **드롭십 적합도 모듈 무력화**

2. **소싱 씨앗 품질**
   정식 분류가 있으면 `"보관/밀폐용기"` 를 씨앗으로 바로 쓸 수 있다.
   지금은 상품명 형태소 파싱에 의존하며, 그 과정에서 `64구`·`실용적인` 같은
   수식어 오탐이 반복 발생했다(결함2, 2회 수정).

3. **네이버 검색 랭킹 '적합도' 손해**
   리서치 항목1: *적합도의 핵심은 '카테고리 선호도'* — 같은 키워드에서 소비자가
   가장 많이 찾는 카테고리에 우선순위가 부여된다. 카테고리 미지정/오지정 상품은
   구조적으로 상위노출에서 밀린다.

> **즉 이 작업은 소싱 기능 개선이 아니라 매출에 직결되는 기반 정비다.**

## 3. 설계 — 4단계

### Step 1. 카테고리 마스터 적재 (선행·필수)

`naver_categories` 0행 → FK를 채울 수 없다. 우선 마스터부터 채운다.

- 소스 1순위: 네이버 커머스API 카테고리 조회 엔드포인트 (정식·최신)
- 소스 2순위: `naver-categories-full.ts` 상수 (이미 코드에 존재, 오프라인 가능)
- 적재 방식: **additive upsert** (`category_code` UNIQUE 기준). 기존 행 삭제 금지.
- 검증: 적재 후 `count(*) > 0`, `depth1` distinct 수가 네이버 대분류 수와 일치하는지.

**주의**: `naver_categories`는 `Product.category_id` FK 대상이다.
`ON DELETE SET NULL` 이므로 마스터 행을 지우면 상품 분류가 조용히 날아간다. **DELETE 금지.**

### Step 2. 제안 품질 개선 (D3/D4 확정률)

현재 실패 사례 2건이 개선 기준이 된다.

- `달항아리` 0건 → 상품명에 카테고리 힌트가 없을 때의 폴백 필요
  (도매매 카테고리 코드, 상품 태그, 이미지 등 보조 신호)
- `아이스트레이` D3 공백 → D2까지만 확정되면 **저장하지 말고 '확인 필요'로 남긴다.**
  불완전 분류를 자동 확정하면 잘못된 카테고리가 랭킹을 더 해친다.

**원칙: 확신 없으면 비워두고 운영자에게 묻는다. 추측으로 채우지 않는다.**

### Step 3. 일괄 백필 — dryRun 우선

기존 12건에 소급 적용. **반드시 2단계로 나눈다.**

```
① dryRun: 상품별 제안 결과 + 신뢰도를 표로 출력. DB 무변경.
② --apply: 운영자가 표를 확인하고 GO 한 건에 한해 반영.
```

- 신뢰도 기준(제안): D4까지 확정 + score 임계 통과 = `auto`,
  D3까지만 = `needs_review`, 0건 = `manual`
- `auto` 만 자동 반영, 나머지는 운영자 확인 큐로.
- **`--apply` 는 운영자 명시 GO 없이 실행 금지** (기존 backfill 원칙과 동일).

### Step 4. 앱 개입점 — 재발 방지

일회성 정비로 끝내면 신규 상품에서 같은 문제가 반복된다.

| 개입점 | 내용 |
|---|---|
| **씨앗심기(상품 등록)** | 카테고리 미지정 시 등록 완료를 막지 않되, 제안 3건을 점수순으로 제시하고 선택 유도 |
| **대시보드 할일** | "카테고리 미지정 N건" 카드 → 클릭 시 확인 큐로 |
| **꼬띠 알림** | 미지정 상품이 임계 이상 쌓이면 주간 알림에 포함 |
| **꽃밭 돌보기 목록** | 미지정 상품에 배지 표시(진단 축), 처방 버튼은 씨앗심기로 연결 |

> 화면 문구는 셀러 실무 용어 + 정원 컨셉. "카테고리 미지정" 대신
> "어느 화단에 심을지 안 정했어요" 류로 검토(카피는 별도 확정).

## 4. 검증 기준 (완료 조건)

이 작업은 아래를 **실행 결과로 증명**해야 완료로 인정한다. tsc 통과는 완료가 아니다.

1. `naver_categories` count > 0
2. `/api/category/suggest` 가 실패 사례 2건(`달항아리`, `아이스트레이`)에 대해
   D3 이상을 반환하거나, 반환 못 하면 `needs_review` 로 정직하게 표시
3. dryRun 표 출력 — 12건 각각의 제안·신뢰도
4. `--apply` 후 `Product.category_id` non-null 건수 증가 확인
5. `dropship-fitness.getDropshipFitness()` 가 기본값 0.6이 아닌 실제 가중치를 반환
6. 브라우저: 상품 목록/상세에서 카테고리가 표시되는지 육안 확인

## 5. 리스크 / 주의

- **FK `ON DELETE SET NULL`**: 마스터 행 삭제 시 상품 분류가 조용히 소실된다.
- **잘못된 자동 분류는 미지정보다 나쁘다**: 네이버 적합도는 카테고리 오지정에
  더 큰 페널티를 준다. 확신 없으면 비워둔다.
- **AI 제안은 추정이다**: Groq 응답을 DB 카테고리로 검증(`validatePageCategory`)한
  뒤에만 채택. 검증 없는 AI 출력 직접 저장 금지.
- **표본 12건은 통계적으로 무의미**: 이 정비의 검증도 골든셋(P0-6)과 연계해야
  신규 상품군에서 재발하지 않는다.
- **`category`(문자열)와 `category_id`(FK) 이중 소스**: 정비 후 어느 쪽이 권위인지
  단일화 필요. 수수료 상수 3중화와 같은 유형의 부채다. 별건으로 등록.
