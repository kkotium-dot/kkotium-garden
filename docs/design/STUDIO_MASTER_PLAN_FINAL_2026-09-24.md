### A-역할 재정의 (대표님 확정 2026-09-24) — 이 항목이 아래 Step 3 설계보다 우선
- **SEO 점검·개선은 씨앗심기 담당**: 상품명·키워드·태그·카테고리·브랜드 진단은 씨앗심기에 이미 구현돼 있으므로 거기서 개선한다. 작업실에 SEO 점검판을 새로 만들지 않는다(중복 금지, #295).
- **꽃단장 작업실 = 썸네일 + 상세페이지 제작 전용**.
- 아래 "Step 3 하이브리드 설계"(적합도/신뢰도/보조 3층, 출처 등급)는 **씨앗심기 SEO 개선 작업의 근거 자료로 이관**한다.

### A-역할 분담 확정 (대표님 2026-09-24) — 아래 "Step 3 하이브리드 설계"를 대체
- **씨앗심기 = 상품정보·SEO의 단일 주인.** 상품명·카테고리·브랜드·속성·태그의 진단·개선은 씨앗심기에서만 한다. 작업실에 같은 점검판을 만들지 않는다(중복 금지, #295).
- **꽃단장 작업실 = 썸네일·상세페이지 제작.** 씨앗심기 확정값을 **읽어서 제작물에 녹인다**(연계·연동). 작업실에서 상품정보를 수정하지 않고, 필요하면 씨앗심기 딥링크로 보낸다.
- 작업실이 씨앗심기 정보를 쓰는 지점(설계 방향):
  1. 썸네일: 제미나이 채팅 합성이미지·씨앗심기 업로드 이미지·대표님 교체 이미지로만 구성(대표님 확정) — 작업실은 이 이미지들의 대표/추가 배치·저장만 담당.
  2. 상세페이지: 씨앗심기 키워드·속성을 **HTML 텍스트 블록**(요약·Q&A·스펙표)에 반영 → 네이버·AI 검색(AEO/GEO)이 읽을 수 있는 글로 제공. 이미지별 설명(alt)도 상품명 고정 대신 씨앗심기 정보 기반으로 다르게.
  3. 연동 방향: 씨앗심기 → 작업실(정보 읽기), 작업실 → 씨앗심기(완성 이미지·상세 HTML 전송, Step 4).
- **[승인 2026-09-24] 작업실 = 3단계**: 1.썸네일 랩 → 2.상세 캔버스(+씨앗심기 정보 반영 패널, 기존 Step 3 흡수) → 3.씨앗심기로 전송. 스텝바에서 SEO 부스터 제거(코드 키는 레거시용으로 유지, `?tab=seo`는 상세로 연결). 아래 하이브리드 설계표의 ①②(적합도·신뢰도) 항목은 **씨앗심기 개선 과제**로 이관.

생성되거나 업로드된 썸네일 개수($N$)에 따라 중앙 스마트 캔버스(55% 영역)의 Grid 비율과 컬럼 수가 자동 계산되어 뷰포트 영역 내에 가장 안정적으로 렌더링됩니다.

```
[개수별 스마트 캔버스 그리드 자동 전환 규칙]

N = 1 ~ 4 개  : 2x2 Grid (기존 기본 뷰)
N = 5 ~ 6 개  : 3x2 Grid (대표님이 자주 사용하시는 6개 최적화 뷰)
N = 7 ~ 9 개  : 3x3 Grid
N = 10 개    : Hero (1) + 3x3 Sub Grid (9) (네이버 최대치 뷰)
```

#### 프론트엔드 CSS 변수 기반 가변 계산 방식

Tailwind 클래스 대신 브랜드 CSS 변수를 적용하여, CSS `grid-template-columns: repeat(auto-fill, minmax(160px, 1fr))` 및 Flexbox 기반 알고리즘으로 캔버스 외곽을 벗어나지 않게 자동 비율을 조정합니다.

### 3. 대표 썸네일 선택 시 레이아웃 & 데이터 구조 변화

특정 썸네일을 클릭하여 **`[👑 대표 썸네일 지정]`** 버튼을 누르거나 호버 클릭 시, 화면 전체는 [Master-Detail Focus Mode]로 즉시 재구조화됩니다.

```
[대표 썸네일 선택 후 화면 재구조화 (Master-Detail Focus)]
좌측: 👑 대표 썸네일 (Hero Slot, 2배 크기, 레드 활성 테두리, [1000x1000 SEO 검증완료])
우측: 추가 썸네일 그리드 (Sub Grid, 추가1~N 배지)
하단: 플로팅 독 — 대표 1개 + 추가 N개 순서 변경 드래그앤드롭
```

#### 1) 시각적 UX 변환 (Visual Transformation)

- **Hero Slot 승격:** 대표로 선택된 썸네일은 좌측(또는 상단)에 **2배 크기의 Hero Slot**으로 크게 이동 및 확대됩니다. 브랜드 메인 컬러인 `var(--gp-primary, #E62310)` 테두리와 함께 `👑 대표` 배지가 고정 부여됩니다.
- **Sub Grid 자동 정렬:** 대표 썸네일을 제외한 나머지 추가 썸네일들(최대 9개)은 우측 **Sub Grid** 영역에 `추가 1`, `추가 2` 순번 배지를 달고 순서대로 자동 정렬됩니다.
- **드래그 앤 드롭 (Re-ordering):** 하단 플로팅 독(Floating Dock)에서 추가 썸네일들의 순서를 마우스 드래그로 손쉽게 바꿀 수 있으며, 순서 변경 시 네이버 등록 순서 데이터가 실시간 업로딩됩니다.

#### 2) 파이프라인 & 백엔드 데이터 변환 (Data State)

- **Zustand / Global State 즉시 반영:**

```
interface ThumbnailState {
  mainThumbnailId: string; // 대표 썸네일 ID
  additionalThumbnailIds: string[]; // 추가 썸네일 ID 배열 (최대 9개)
  totalCount: number; // 현재 썸네일 총 개수 (1~10)
}
```

- **Step 2 (상세페이지 캔버스) 자동 연동:** 대표 썸네일로 확정되는 순간, Step 2 상세페이지 최상단 섹션[메인 비주얼]에 해당 이미지가 1000x1000px 고화질 원본으로 자동 삽입됩니다.
- **Step 3 (SEO 관제탑) 검증 연동:** 우측 SEO 관제탑에서는 선택된 '대표 썸네일'의 해상도, 텍스트 가독성, Alt 태그 누락 여부를 최우선으로 정밀 진단합니다.

### 4. 클로드(Claude) 연동용 데이터 상태 지시서

```
[System/Handoff: 썸네일 랩(Step 1) - 가변 그리드 & 대표 썸네일 Hero 승격 상태 연동]

1. 네이버 규정 준수 (Fact Checked)
- 대표 썸네일 1개 + 추가 썸네일 최대 9개 (총 10개) 슬롯을 가변적으로 수용하도록 Zustand 상태를 설계하십시오.

2. Dynamic Layout Calculation
- `thumbnails.length`에 따라 CSS Grid 컬럼을 동적으로 분기하십시오.
  - 1~4개: `grid-template-columns: repeat(2, 1fr)`
  - 5~6개: `grid-template-columns: repeat(3, 1fr)`
  - 7~9개: `grid-template-columns: repeat(3, 1fr)`
  - 대표 선택 시: Left Hero Slot (flex: 2) + Right Sub Grid (flex: 3) 구조로 CSS Flex/Grid 전환

3. State Transformation Logic
- `selectMainThumbnail(id: string)` 액션 실행 시:
  1. `mainThumbnailId`를 업데이트하고 해당 노드에 `var(--gp-primary)` 2px Border 적용.
  2. 선택된 노드를 Sub Grid에서 제거하고 Hero Slot 영역으로 UI 승격.
  3. 나머지 슬롯은 `additionalThumbnailIds` 배열 순서대로 '추가 1 ~ N' 번호 배지 부여.
  4. Step 2 상세페이지 캔버스 Top Section의 `backgroundImage`로 해당 URL 자동 전송.
```

스마트스토어 규정과 실무진의 작업 동선을 반영하여, 썸네일 개수가 늘어나도 스크롤 압박 없이 직관적으로 대표 썸네일을 지정하고 순서를 정돈할 수 있는 유료 B2B SaaS급 환경이 마련되었습니다.
