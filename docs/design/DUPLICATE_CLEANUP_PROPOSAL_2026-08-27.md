## 2. 출처 규명 (환각 없이 실측)

### 2-1. 스텐빨대 2건 = 테스트 잔재 (강한 추정)
- `source=NATIVE`(수동), supplierPrice=0, salePrice=0, supplier_product_code=null → **공급사 연결 없는 빈껍데기**.
- 생성 08-27 07:13/07:17 (오늘·3분 간격) — UCE-7 매처를 프로덕션 씨앗심기 UI에서 검증할 때('실리콘주걱'·'스텐빨대' 입력) 생성된 테스트 데이터로 추정.
- 카테고리·이미지·가격 전무 → 실제 판매 의도 상품 아님.

### 2-2. 64구 아이스틀 = 실제 상품 중복
- 05-28 원본(이미지 O) vs 08-08 재생성(이미지 O). 실제 소싱 상품의 중복 등록.
- 08-08 것이 나중 생성이므로 삭제 후보(단, 08-08 것에 더 나은 데이터 있는지 운영자 확인 권고).

## 3. 상신 — 삭제 대상 (운영자 GO 후 실행)

```sql

DELETE FROM "Product" WHERE id IN (

  'cmtb6wlwf0005rsh5vac50eab'   -- 스텐빨대 07:17

-- 64구 아이스틀 중복 1건 (08-08 재생성분)
DELETE FROM "Product" WHERE id = 'cmsjzlf0r0002ocar8mglzixf';
```

## 4. 안전성 체크
- 4건 모두 **미발행(naverProductId NULL)** → 네이버 스토어 라이브 상품 아님. 삭제해도 스토어 무영향.
- 스텐빨대 2건: 발행·리뷰·판매실적 전무 → 처분권고상 DELETE_SAFE(자산 없음).
- 64구 08-08분: 삭제 전 05-28 원본이 온전한지 운영자 최종 확인(둘 중 데이터 나은 쪽 유지).
- **연관 레코드 확인 필요**: sourcing_opportunity_records·daily_recommendations 등에서 이 id 참조 있으면 FK/정합성 확인(삭제 전 Code가 점검).

## 5. 개입점 (전 상품 공통 — 재발 방지)
- **근본 제안**: 씨앗심기 UI에 "동일 상품명 이미 존재" 경고(중복 생성 차단). 스텐빨대 3분 간격 중복이 이게 없어서 발생.
- 테스트 시 NATIVE·가격0 빈껍데기가 프로덕션 DB에 쌓이지 않게, 검증은 dryRun/로컬 우선.

## 6. 의존성·범위

- 긴급도: 낮음(미발행·무영향). 단 테스트 잔재는 위생상 정리 권고.
