# KKOTTI_DAILY_SOURCING_V2 — 꼬띠 데일리 소싱 추천 시스템 개선 설계

> 상태: **설계 확정**(2026-08-07 Desktop). 운영자 방향 확정 반영 + 도매매 API 실측 근거.
> 한 줄 요약 — **다중 발굴 렌즈**(급상승·시즌선점·니치·블루오션·꿀통·황금·스테디 + 레드오션 경고)로 넓게 발굴한 트렌드 신호를 **내 공급사 안에서 실제 뗄 수 있는 최적 상품과 매칭**해 매일 아침 10개 추천. 디스코드=렌즈별 모바일 요약, 앱=상세 완결. 품절 대체상품 축 연계.

## 0. 문제 정의 (운영자 방향)

기존 소싱 추천은 **"트렌드 키워드 → 도매 검색"** 한 방향이다. 운영자 요청:
1. **트렌드 정보도 알려주면서** — 세상이 뜨는 신호를 계속 제공하되,
2. **공급사 기준 최적 상품도 추천** — 내가 실제 거래하는 공급사(도매매 셀러) 안에서 그 트렌드에 맞는 상품을 매칭.
3. **품절 대체상품** 등 확장 아이디어.
4. **★ 발굴 관점(렌즈)을 협소하게 잡지 말 것** — "지금 뜨는 실시간 키워드" 하나가 아니라, 시즌 트렌드·니치·급상승·스테디 등 **포괄적 다각도**로 나눠서 제안(2026-08-07 추가 방향).

핵심: 세 층위를 **결합**한다 — "**다중 렌즈로 발굴한 트렌드 신호** × **공급사 상품** = 내가 지금 뗄 수 있는 검증된 기회". 발굴 렌즈(§3-0)가 넓어지고, 각 렌즈 결과가 공급사 축과 매칭된다.

## 2. ★ 실현 가능성 실측 — 공급사 축 (도매매 API 공식 문서)

**도매매 OpenAPI v4.1 getItemList는 `id`(판매자 아이디) 파라미터를 지원한다**(공식 레퍼런스 확인, 2026-08-07):
> "상품목록 검색을 위하여 아래 검색 조건 중 하나 이상의 파라미터 설정이 필요합니다. 기획전번호(ev), 카테고리(ca), **아이디(id)**, 검색어(kw), 상품번호(itemNo)"

- 즉 `getItemList?id={domeggookSellerId}&ca={카테고리}` 조합으로 **특정 공급사의 특정 카테고리 상품**을 조회 가능.
- 응답에 `categoryId`·`categoryName`·`sellerLv`(셀러 등급)·`price`·`unitQty` 포함.
- **판매중인 상품만 반환**(판매중지·종료·품절·단종 제외) → 항상 살아있는 상품. 품절 대체 축에도 유리.
- 우리 `Supplier.domeggookSellerId`(이미 존재)와 직결 → **인프라 절반 이미 있음**.

→ 공급사 축 B는 **새 API가 아니라 기존 `searchDomeggookMarket()`에 `id` 파라미터 추가**로 구현 가능. 난이도 낮음.

## 3. ★ 개선 설계 — 트렌드 × 공급사 결합

### 3-0. ★ 다중 소싱 렌즈 — 발굴 관점을 넓힌다 (운영자 방향 4)

기존 발굴이 "DataLab 지금 뜨는 키워드" 하나로 협소했다. 발굴 **렌즈 자체를 여러 개**로 나눠, 각 렌즈가 서로 다른 기회를 포착한다. `recommendation-type.ts`(황금/니치/시즌 분류기 이미 존재)를 **발굴 렌즈로 승격·확장**한다.

| 렌즈 | 포착하는 기회 | 신호원(기존 재활용) | "언제 좋은가" |
|---|---|---|---|
| 📈 **급상승** | 지금 막 뜨기 시작 | DataLab 트렌드 상승률 | 선점 — 레드오션 되기 전 |
| 🗓️ **시즌 선점** | 곧 다가올 시즌(지금은 잠잠) | `naver-margin-advisor` seasonality peak 근접 판정 | 미리 준비 — 시즌 2~6주 전 |
| 💎 **니치** | 경쟁 적은 틈새 | 검색량 中 + 경쟁 極低 + entryBarrier 低 | 꾸준한 소량 마진 |
| 🌊 **블루오션** | 수요 있고 경쟁 낮음 | blueOceanScore ≥ 70 | 신규 진입 최적 |
| 🍯 **꿀통(마진)** | 마진 우수 상품 | supplyPriceRange 대비 예상 판매가 | 수익성 우선 |
| 🏆 **황금키워드** | 검색 高 + 마진 高 | seoScore↑ AND roiScore↑ | 대형 기회(경쟁 감수) |
| 📚 **스테디셀러** | 트렌드 무관 꾸준 수요 | 검색량 안정 + 변동성 低(신규 신호) | 리스크 낮은 기본 라인 |
| ⚠️ **레드오션 회피** | 경쟁 과열 경고(발굴 아닌 필터) | uniqueSellersInTop 多 + 경쟁 高 | 진입 말라는 신호 |

**설계 원칙**:
- 매일 10개를 **렌즈별로 배분**한다(예: 급상승 2·시즌선점 2·니치 2·블루오션 2·꿀통 1·스테디 1). 배분 비율은 상수로 조정 가능(하드코딩 금지).
- 한 상품이 **여러 렌즈에 동시 해당** 가능(예: 급상승📈 + 블루오션🌊). 배지를 다중 표시.
- 렌즈는 **발굴 소스**이고, 각 렌즈 결과가 §3-1의 공급사 축과 매칭돼 "이 렌즈로 찾은 기회를 내 공급사가 취급하는가"를 확인한다.
- ⚠️ 레드오션은 발굴이 아니라 **경고 렌즈** — 다른 렌즈로 뽑힌 후보가 레드오션이면 배지로 경고(진입 판단은 운영자, #327 정신).
- **시즌 선점이 핵심 차별점**: 남들이 "지금 뜨는 것"을 좇을 때, 곧 올 시즌을 2~6주 미리 준비 → 시즌 피크에 이미 상위 노출(스마트스토어 SEO는 판매 이력·리뷰 누적이 상위 노출에 유리하므로 선점 효과 큼).

### 3-1. 통합 소싱 파이프라인 (다중 렌즈 × 공급사 → 10개 엄선)

```
[다중 렌즈 발굴]  §3-0의 8개 렌즈로 후보 키워드/카테고리 발굴
     │            (급상승·시즌선점·니치·블루오션·꿀통·황금·스테디 + 레드오션 경고)
     ├─→ 각 후보로 ↓
     │
[공급사 축]    내 공급사(domeggookSellerId)들의 상품을
     │         getItemList?id=셀러&kw=키워드(or ca=카테고리)로 조회
     │         = "이 렌즈로 찾은 기회에 맞는, 내가 실제 거래하는 공급사의 상품"
     │
[전체시장 축]  공급사에 없으면 키워드 전체 도매 검색(신규 공급처 발굴용)
     │
     ▼
[통합 스코어러]  각 후보에 렌즈 배지(다중) + 공급사 프리미엄 가점 + categoryMismatch(트랙③)
     ▼
[10개 엄선]    렌즈별 배분 + 공급사 매칭 우선(내가 뗄 수 있음)
     ▼
[디스코드 요약] + [앱 상세]
```

### 3-2. 공급사 프리미엄 (핵심 차별점)

같은 트렌드 키워드라도, **내 공급사가 그 상품을 이미 취급**하면 가점:
- ✅ 거래 중인 공급사 = 배송·정산·합배송 이미 세팅됨(마찰 0)
- ✅ 공급사 등급(sellerLv)·기존 마진(defaultMargin) 알고 있음
- ✅ 합배송 가능(bundleCapable) 공급사면 배송비 이점

→ 추천 상품에 **"내 공급사 [OO] 취급" 배지** = 운영자가 "지금 당장 뗄 수 있는 것"을 즉시 인지.

### 3-3. 배지 = 렌즈(§3-0) + 공급사

각 추천 상품은 §3-0의 렌즈 배지(다중 가능)에 더해 공급사 배지를 단다. 기존 `recoType`(황금🏆/니치💎/시즌🗓️) 인프라를 §3-0의 8개 렌즈로 확장하고, 여기에:
| 추가 배지 | 판정 |
|---|---|
| 🏪 내 공급사 | domeggookSellerId 매칭됨(공급사 프리미엄 §3-2) |
| ⚠️ 카테고리 확인 | categoryMismatch suspect(트랙③) — 동음이의 의심 |

### 3-4. 디스코드 = 모바일 요약, 앱 = 완결 (UX 핵심)

**디스코드**(모바일 3초 스캔 — 렌즈별 그룹핑, 상품당 2~3줄). 운영자가 "다각도로 나눠서" 보길 원하므로 렌즈 섹션으로 묶는다:
```
🌷 꼬띠의 오늘 소싱 밭 (8/8)
10개 · 내 공급사 매칭 4 · 시즌 선점 2

📈 지금 급상승
 · 차량용 방향제  블루오션82 · 🔍8,900 · [OO상사]🏪
 · 미니 가습기  62 · 🔍5,200

🗓️ 시즌 선점 (곧 와요)
 · 전기요  🍯마진우수 · 공급 8k~14k · [XX무역]🏪
 · 손난로  검색 상승 시작

💎 니치 (틈새)
 · 케이블 정리함  경쟁낮음 · [OO상사]🏪

👉 앱에서 전체 확인·소싱 [바로가기]
```
- 렌즈 섹션 헤더 + 상품당 2~3줄(상품명 + 핵심 배지 + 숫자 1~2 + 공급사🏪). 정원 컨셉은 헤더 인사만(#318).
- ⚠️ 레드오션 후보는 별도 섹션 없이 해당 상품에 경고 배지만.
- 나머지(마진 계산·도매 매칭 목록·categoryMismatch 상세·경쟁 상세·낙점 버튼)는 전부 앱.

**앱**(성장·소싱 화면 확장):
- 디스코드 10개가 그대로 앱 소싱 위젯에 연동(이미 SourcingRecommendWidget 존재).
- 각 상품 카드: 트렌드 지표 + 공급사 매칭 정보 + categoryMismatch 경고(트랙③) + 도매 매칭 + 낙점.
- 공급사 매칭 상품은 "이 공급사에서 바로 소싱" 딥링크.

## 4. 💡 확장 아이디어 — 품절 대체상품 연계

### 4-1. 품절 → 같은 공급사 대체 후보 (자동)
내 상품이 공급 단절(`source-gone.ts` 판정)되면:
- 그 상품의 공급사(domeggookSellerId)로 `getItemList?id=셀러&ca=같은카테고리` 조회
- = **같은 공급사·같은 카테고리의 살아있는 상품**(API가 품절 제외하므로 자동으로 판매중만) → 대체 후보
- 배송·정산 세팅이 이미 같은 공급사라 전환 마찰 최소
- 소싱 추천 파이프라인과 **동일 엔진 재사용**(전 상품 공통 #62)

### 4-2. "대체 소싱 카드" — 소싱 추천에 품절 대응 슬롯
데일리 10개 중 일부를 "내 품절 상품의 대체 후보"로 동적 할당:
- 품절 상품이 있으면 → 대체 후보를 우선 추천(급함)
- 없으면 → 신규 트렌드 발굴로 채움
- 운영자 관점: "당장 매출 구멍(품절) 메우기" > "신규 발굴" 우선순위 반영

### 4-3. 추가 제안 (Co-Founder 관점)
- **소싱 히스토리 학습**: 운영자가 낙점(interested/sourcing_started)한 상품의 카테고리·공급사·가격대를 학습 → 다음 추천 개인화("당신이 자주 뗀 [주방용품] 카테고리 신상").
- **경쟁 진입 타이밍**: 급상승 트렌드(📈)는 "지금 안 들어가면 레드오션 됨" 경고 → 선점 압박 UX.
- **합배송 번들 제안**: 같은 공급사에서 여러 상품 추천 시 "합배송 가능 — 배송비 절감" 묶음 제안(bundleCapable 활용).

## 5. 전 상품 공통 시스템 관점

단건 기능이 아니라 **소싱 파이프라인 구조 개편**:
```
                    ┌─ 트렌드 축(기존) ─┐
소싱 엔진 통합 ─────┼─ 공급사 축(신규) ─┼→ 통합 스코어(SEO 다차원+공급사 프리미엄)
                    └─ 전체시장 축 ─────┘         ↓
                                          10개 엄선 → 디스코드 요약 + 앱 상세
품절 판정(source-gone) ────────────────────→ 대체 후보(같은 공급사) ─→ 소싱 슬롯 재활용
낙점 히스토리 ──────────────────────────────→ 개인화 학습
```
- 공급사 축·품절 대체·개인화가 **하나의 소싱 엔진**을 공유(중복 구현 없음).
- 개입점: 소싱 위젯(앱)·디스코드(알림)·품절 대응 큐(operator action)에 자연스럽게 노출.
