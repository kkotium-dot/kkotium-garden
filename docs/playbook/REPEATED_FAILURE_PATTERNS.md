## 2. 완료 보고 전 강제 체크리스트

### C1. 반영 경로 (F1·F2 방지)

```bash
git status --porcelain                 # 미커밋 0건이어야 함
git log --oneline -1                   # 커밋 해시 확보
git merge-base --is-ancestor <해시> origin/main && echo MERGED || echo "NOT IN MAIN"
```
- [ ] 미커밋 0건
- [ ] **커밋 해시를 보고에 명시** (해시 없는 완료 보고는 무효 — #345)
- [ ] main 병합 여부까지 확인. push ≠ 병합

### C2. 연결 증명 (F3 방지)

```bash
grep -rn "<새모듈명>" src/ --include=*.ts --include=*.tsx | grep -v "<새모듈파일>"
```
- [ ] 호출부가 **1곳 이상** 존재
- [ ] 그 호출부가 **실제 실행 경로**인가 (죽은 코드·주석 아님 — #292)
- [ ] 신규 모듈은 **호출부 연결까지가 완료**다

### C3. 실행 증명 (F4 방지)

- [ ] 실제 데이터로 **함수를 실행**하고 **출력을 보고에 붙여넣음**
- [ ] tsc 0은 완료 근거로 인정하지 않음 (#344)
- [ ] 실행 불가 시 **지어내지 말고** 검증 스크립트를 만들어 상대 레인에 위임

### C4. 일반화 증명 (F5 방지)

- [ ] 골든셋(`npm run test:seeds`) 통과율 보고
- [ ] **골든셋에 없는 입력**으로 교차검증 (자기 테스트 자기 통과 방지)
- [ ] 자사 데이터 표본이 20건 미만이면 **합성 테스트 셋 필수**

### C5. 데이터 정합 (신규 — 카테고리 사례)

- [ ] 코드가 참조하는 **마스터 테이블이 실제로 채워져 있는가**
      (`naver_categories` 0행 → `dropship-fitness.ts` 전면 무력화 사례)
- [ ] 기본값 폴백이 **조용히 전건 적용**되고 있지 않은가
- [ ] 분류·매칭은 **정답지에서 선택**하게 하고, 저장 직전 **실재 검증** (#346)

### C6. 워크트리·lock 위생 (신규 — #347)

```bash
ls -la .git/*.lock 2>&1                # 있으면 mtime·프로세스 확인 후에만 제거
git worktree list
git status --short   # 각 워크트리에서 실행 — ahead=0이어도 필수
```
- [ ] `.git/*.lock` 잔재가 있다면 살아있는 git 프로세스가 없음을 확인한 뒤 제거(추측 금지)
- [ ] 워크트리 정리는 ahead/behind만 보지 않고 **각 워크트리의 미커밋(staged/untracked) 여부**까지 확인
- [ ] ahead=0인데 미커밋이 있으면 그 내용이 이미 다른 곳(main 등)에 존재하는 중복인지 대조 후에만 삭제
- [ ] 워크트리·브랜치 삭제는 **사용자 승인 후에만** 실행 (되돌리기 어려운 작업)
