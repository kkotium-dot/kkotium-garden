# 꽃틔움 스토어 — KKOTIUM GARDEN 개발 작업원칙

> 프로젝트: KKOTIUM GARDEN
> 목적: 1인 셀러의 상품 소싱·상품등록·이미지/상세페이지 제작·SEO·재고·판매관리를 자동화하는 B2B SaaS형 백오피스

---

## 1. 최우선 원칙

### 1.1 거짓 결과 금지

실제로 실행하지 않은 테스트를 통과했다고 보고하지 않는다.

실제 브라우저에서 확인하지 않은 기능을
"브라우저 테스트 완료"라고 표현하지 않는다.

환경상 실행할 수 없는 경우:

1. 무엇을 실행할 수 없는지
2. 왜 실행할 수 없는지
3. 사용자가 무엇을 실행해주면 되는지
4. 그 결과를 받은 뒤 무엇을 검증할 것인지

를 명확하게 보고한다.

## 2. 개발 순서

모든 기능은 다음 순서를 따른다.

1. 현재 코드 상태 확인
2. 기존 기능 재사용 가능성 조사
3. 요구사항 정의
4. 구현
5. TypeScript 검사
6. 단위/통합 테스트
7. 실제 API 테스트
8. 실제 브라우저 테스트
9. 실패 케이스 테스트
10. 회귀 테스트
11. 결과 기록
12. 다음 작업 진행

한 단건의 오류만 수정하고 끝내지 않는다.

같은 종류의 오류가 다시 발생하지 않도록
공통 원인과 구조를 수정한다.

## 3. 교차검증 원칙

외부 정보가 필요한 경우 최소 2개의 신뢰 가능한 출처를 비교한다.

우선순위:

1. 공식 문서
2. 공식 API 문서
3. 공식 GitHub / 공식 저장소
4. 신뢰 가능한 기술 문서
5. 실제 실행 결과

블로그나 커뮤니티 글만으로 기능을 확정하지 않는다.

AI의 기억만으로 브라우저 API 또는 플랫폼 정책을 단정하지 않는다.

---

## 4. 환각 제거

다음 표현은 실제 근거가 없으면 사용하지 않는다.

- 확실히 된다
- 문제없다
- 완벽하게 된다
- 지원한다
- 테스트 통과
- 배포 완료

반드시 다음 중 하나를 근거로 한다.

- 실제 코드
- 실제 터미널 결과
- 실제 브라우저 테스트
- 공식 문서
- 실제 API 응답

## 5. 브라우저 Collector 원칙

Chrome과 Safari를 모두 지원한다.

가능하면 공통 Web Extension 코드를 사용한다.

Collector는 다음 데이터를 탐색한다.

### 이미지

- img.src
- img.currentSrc
- srcset
- picture/source
- lazy-load 속성
- CSS background-image
- 페이지 내 이미지 URL

### 동영상

- video.currentSrc
- video.src
- source[src]
- video poster
- 페이지에 노출된 동영상 URL
- 가능한 경우 실제 미디어 요청 정보

미디어 유형은 다음과 같이 구분한다.

- IMAGE
- VIDEO_FILE
- VIDEO_STREAM
- POSTER
- UNKNOWN

---

## 6. 동영상 한계

다음은 일반 MP4와 동일하게 취급하지 않는다.

- blob:
- MediaSource
- HLS
- DASH
- DRM
- signed temporary URL
- 인증이 필요한 스트림

수집 불가능한 미디어를 성공으로 표시하지 않는다.

---

## 7. 저장 구조

기존 저장 시스템을 우선 재사용한다.

Canonical storage:

product-assets/{productId}/{stage}/

AssetRegistry와 실제 Storage의 불일치를 방지한다.

새로운 별도 저장 시스템을 기능별로 임의 생성하지 않는다.

---

## 8. Asset Registry

새로 수집한 자산은 가능하면 다음 정보를 유지한다.

- productId
- stage
- fileName
- path
- sourceTag
- variant
- createdAt
- width
- height

Collector sourceTag 예:

collector_chrome
collector_safari
collector_manual

---

## 9. 중복 방지

같은 URL을 여러 번 수집해도 중복 저장하지 않는다.

가능하면 다음 단계로 중복을 판별한다.

1. canonical URL
2. normalized URL
3. file hash
4. 기존 AssetRegistry
5. storage path

---

## 10. 보안

브라우저 확장 프로그램에 서버 비밀키를 넣지 않는다.

Supabase service role key를 extension에 넣지 않는다.

Anthropic/Gemini/Naver 등의 secret key를 extension에 포함하지 않는다.

브라우저는 꽃틔움 서버의 제한된 API만 호출한다.

---

## 11. 인증

현재 프로젝트의 인증 구조를 먼저 확인하고 재사용한다.

임의로 새로운 인증 체계를 만들지 않는다.

Collector가 서버에 접근할 경우
인증/세션/토큰 구조를 명확히 한다.

---

## 12. CORS

Chrome/Safari extension에서 서버 API를 호출할 경우
origin과 인증 방식을 명확하게 설계한다.

개발 편의를 위해 무조건
Access-Control-Allow-Origin: *
를 적용하지 않는다.

---

## 13. 상품 식별

상품은 이름만으로 식별하지 않는다.

우선순위:

1. productId
2. SKU
3. sellerCode
4. source URL
5. 상품명

상품명이 동일할 수 있다는 것을 항상 전제로 한다.

---

## 14. UI/UX 원칙

꽃틔움 앱은 일반적인 관리자 페이지가 아니라
프리미엄 B2B SaaS를 목표로 한다.

원칙:

- 정보 계층을 명확하게 한다.
- 기능을 한 화면에 무작정 늘리지 않는다.
- 반복 작업을 줄인다.
- 주요 CTA를 명확하게 한다.
- 상태를 색보다 구조와 텍스트로도 전달한다.
- 작업 흐름이 왼쪽→오른쪽 또는 위→아래로 자연스럽게 이어지게 한다.
- 불필요한 모달을 줄인다.
- 중요한 작업의 성공/실패 상태를 즉시 보여준다.

## 21. 프로젝트 최종 방향

KKOTIUM GARDEN은 단순한 상품관리 프로그램이 아니라

"상품을 발견하고 → 수집하고 → 분석하고 → 가공하고 → 등록하고 → 관리하고 → 다시 개선하는"

상품 운영 자동화 시스템을 목표로 한다.

모든 신규 기능은 이 전체 흐름을 단순하게 만드는 방향으로 설계한다.
